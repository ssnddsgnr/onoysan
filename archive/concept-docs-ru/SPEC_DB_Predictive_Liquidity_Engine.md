Этот документ определяет, как база данных PostgreSQL превращается из хранилища в предсказателя. Мы описываем математический аппарат, который позволяет детектировать финансовые проблемы (кассовые разрывы) строго алгоритмически, не прибегая к помощи нейросетей. Это гарантирует, что предупреждение «У вас закончатся деньги через 5 дней» — это математический факт, а не галлюцинация.


--------------------------------------------------------------------------------

**Концепция:** Deterministic Hard Engine (Детерминированный жесткий движок) **Роль:** «Финансовый Радар». Сканирование временной шкалы на предмет отрицательных балансов. **Принцип:** «Математика — в ядре, интерпретация — в ИИ». ИИ запрещено считать прогнозы самостоятельно.

# 1. Архитектура Прогнозирования

Модуль прогнозирования разделен на два слоя ответственности:

**Hard Engine (DB Layer):** Выполняет расчеты на PL/pgSQL. Оперирует цифрами, датами и диапазонами. Выдает бинарный результат: «Разрыв будет/не будет».

**Soft Simulation (AI Layer):** Получает данные от Hard Engine и генерирует советы («Сократи расходы на такси») или объяснения («Это из-за страховки»). **Этот документ описывает только Hard Engine.**

## 1.1. Входные данные для расчета

Функция прогноза собирает данные из трех источников внутри БД:

**Start Point (Точка старта):**Источник: `user_snapshots.safe_to_spend` (или `net_cash`).Значение: Реальные свободные деньги пользователя «здесь и сейчас».

# 4. Система Уровней Тревоги (Alarm Levels)

Результат работы функции — это JSON-объект, содержащий статус риска. Бэкенд реагирует на этот статус вызовом соответствующих ИИ-агентов.

| Уровень (Code) | Условие (Condition) | Реакция Системы (Action) |
| --- | --- | --- |
| LEVEL 0 (Green) | Balance min 	​  >0 на всем горизонте. | Silent. Система работает штатно. В UI показывается "Прогноз: Стабильно". |
| LEVEL 1 (Blue) | Незначительный разрыв (< 5% от дохода) в конце месяца. | Passive. Запись в nostradamus_outbox (тихий дайджест). Предложение пересмотреть мелкие траты. |
| LEVEL 2 (Yellow) | Разрыв ощутимый, но горизонт > 14 дней. | Active. Уведомление при следующем входе. «Через 2 недели аренда, нам не хватает $100». |
| LEVEL 3 (Red) | Разрыв неизбежен на горизонте < 7 дней. | Critical. Мгновенный Push. Активация агента Sana Zen (Crisis Mode). «Внимание: Кассовый разрыв через 4 дня!». |

# 5. Триггеры запуска (Execution Context)

Расчет прогноза — операция средней тяжести. Она не запускается на каждый клик.

## 5.1. Событийная модель

Пересчет запускается асинхронно (через очередь или триггер `AFTER STATEMENT`) при следующих событиях:

**Крупная транзакция:** Списание/зачисление суммы > X% от текущего баланса.

**Изменение обязательств:** Добавление нового долга или подписки.

**Reality Sync:** Ручная корректировка баланса пользователем.

## 5.2. Кэширование результата

Результат прогноза сохраняется в поле `user_snapshots.liquidity_status` (JSONB).

Это позволяет ИИ-агентам (Консильери) мгновенно отвечать на вопрос «Как у меня дела?», просто читая этот JSON, без запуска пересчета.

# 6. Песочница (Simulation Mode)

Функция `fn_forecast_liquidity` поддерживает параметр `p_simulated_transaction`.

**Сценарий:** Пользователь спрашивает: *«Что если я куплю новый iPhone сейчас?»*.

**Логика:**ИИ формирует JSON виртуальной транзакции (Расход $1000).Бэкенд вызывает `fn_forecast_liquidity` с этим параметром.Движок "на лету" вычитает $1000 из стартового баланса и прогоняет алгоритм.**Результат:** Если статус меняется с `Green` на `Red`, ИИ отвечает: *«Это создаст кассовый разрыв через 20 дней»*.

# Резюме

**DB Predictive Engine** превращает базу данных в оракула. Мы не гадаем на кофейной гуще; мы используем жесткую арифметику, чтобы предсказывать будущее. Это обеспечивает **Trustability** (Доверие): пользователь знает, что если Sana молчит — значит, математически всё в порядке.

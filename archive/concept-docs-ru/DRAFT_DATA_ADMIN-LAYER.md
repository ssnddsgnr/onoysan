Этот документ является корректирующим дополнением к общей архитектуре Sana. Он фокусируется исключительно на **Административном слое (схема ****system****)**, описывает назначение его таблиц и логику их взаимодействия с приватным финансовым ядром (`ledger`) и слоем идентификации (`auth`).


--------------------------------------------------------------------------------

**Статус:** Corrective Specification

**Логическая зона:** Схема `system` (Global Knowledge & Administrative Control).

**Физическая изоляция:** Единая БД с разделением прав доступа на уровне ролей СУБД.


--------------------------------------------------------------------------------

# 1. Реестр таблиц административного слоя

## 1.1. Слой глобальных справочников (Global Knowledge)

**fx_rates_history**: Глобальный архив курсов валют и криптовалют. Хранит данные с разной детализацией (минуты, часы, дни) и используется для пересчета всех операций в базовую валюту пользователя.

**categories_dictionary**: Централизованная таксономия категорий и подкатегорий. Служит эталоном для ИИ при классификации транзакций, обеспечивая единообразие аналитики для всех пользователей.

**merchant_profiles**: Справочник известных торговых точек (мерчантов). Сопоставляет названия из банковских выписок с человекочитаемыми брендами и категориями по умолчанию.

## 1.2. Слой технического состояния (Technical State)

**blockchain_cursors**: Хранит «указатели» синхронизации для крипто-движка `sana-crypto-sync`. Фиксирует номер последнего обработанного блока в каждой сети (BTC, ETH и др.), чтобы избежать дублирования данных.

**external_integrations**: Управляет состояниями внешних подключений (Bank API, Exchange API). Хранит статусы синхронизации и зашифрованные токены доступа.

**import_batches**: Группирует записи, загруженные через файлы (CSV/Excel). Позволяет системе идентифицировать массив транзакций как единый «пакет» для возможности его массового удаления или отката.

## 1.3. Слой безопасности и управления (Governance & Security)

**system_audit_logs**: Неизменяемый журнал критических событий. Фиксирует изменения прав доступа в `access_grants`, модификацию налоговых правил и любые действия администраторов системы.

**system_announcements**: Управляет вещанием (Broadcast Service). Содержит тексты и параметры таргетинга для системных уведомлений о техработах или обновлениях платформы.

**ai_usage_metrics**: Технический учет ресурсов ИИ. Фиксирует количество использованных токенов и типы моделей (Gemini/Claude) для контроля эксплуатационных затрат.

# 2. Логика взаимодействия слоев

## 2.1. Взаимодействие с Ledger (Приватное ядро)

Административный слой выступает в роли «поставщика контекста» для финансовых операций:

**Пересчет валют:** При записи транзакции в `ledger_transactions` бэкенд запрашивает актуальный курс из `fx_rates_history` для фиксации моментального снапшота стоимости.

**Обогащение данных:** При попадании транзакции в `pending_layer` система сопоставляет её с `merchant_profiles` и `categories_dictionary`, чтобы предложить пользователю уже заполненный черновик.

**Целостность импорта:** Каждая запись в Ledger, созданная через импорт, получает FK на `import_batches`, что позволяет проводить аудит источника данных.

## 2.2. Взаимодействие с Когнитивным слоем (AI & UX)

Административный слой корректирует поведение ИИ-агентов и интерфейса:

**Информирование:** Дирижёр проверяет наличие активных записей в `system_announcements` и внедряет их в `chat_messages` пользователя, если они соответствуют его группе.

**Идентификация проблем:** Если `blockchain_cursors` не обновлялись длительное время, ИИ получает уведомление о сбое синхронизации и может проактивно сообщить пользователю о задержке отображения баланса.

## 2.3. Взаимодействие со слоем Auth (Identity)

**Аудит доступа:** При изменении метаданных пользователя в `auth.users_metadata` или прав доступа, запись об этом событии дублируется в `system.system_audit_logs` для обеспечения прозрачности безопасности.


--------------------------------------------------------------------------------

# 3. Режим доступа (Access Policy)

Для обеспечения безопасности уровня **Fortress** применяются следующие правила:

**ReadOnly:** Пользовательские процессы и ИИ-агенты имеют доступ к схемам `system` только для чтения (справочники, курсы).

**WriteOnly:** Технические воркеры (сканеры блокчейна, сборщики курсов) могут записывать данные в свои курсоры и архивы, но не имеют доступа к чтению персональных транзакций пользователей.

**Admin Access:** Доступ к модификации таблиц `system_announcements` и `system_audit_logs` разрешен только через административный контур с обязательной фиксацией сессии.

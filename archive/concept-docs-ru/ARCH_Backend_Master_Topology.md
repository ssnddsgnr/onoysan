# 1. Архитектурная Философия: Исполнительная Власть

Backend Sana спроектирован не как монолит, содержащий всю бизнес-логику, а как **Высокопроизводительный Оркестратор**. Его главная задача — управление потоками данных, ресурсами и безопасностью, в то время как «математическая истина» делегирована в PostgreSQL, а «интерпретация» — в AI-слой.

## Ключевые паттерны:

**Stateless & Fearless:** Ядро не хранит состояние (оно в БД/Redis) и не боится сбоев в подсистемах, автоматически перезапуская их.

**Panic Isolation:** Сбой в тяжелых вычислениях (например, при генерации PDF) не должен влиять на обработку чатов. Для этого рискованные задачи вынесены в отдельные процессы,.

**Dumb Pipe, Smart Endpoints:** Бэкенд знает *кому* передать данные (Агенту или БД), но не пытается интерпретировать их смысл самостоятельно.

### 2. Центральное Звено: sana-core (The Sun)

**sana-core** — это единый бинарный процесс на Rust, работающий в режиме `Master`. Он отвечает за прием соединений, валидацию и маршрутизацию.

### 3. Орбитальная система: Спутники (The Satellites)

Для обеспечения надежности, тяжелые и рискованные задачи вынесены в изолированные бинарные файлы. Они не имеют публичного API и общаются с Ядром через **gRPC over Unix Domain Sockets** (для локального деплоя) или TCP (для разнесенного),.

#### Реестр Спутников:

| Спутник | Роль и Ответственность | Режим работы |
| --- | --- | --- |
| sana-nostradamus | Predictive Engine. Моделирование сценариев будущего (Монте-Карло), расчет кассовых разрывов. Требует много CPU. | Slow Loop (Фоновый) |
| sana-crypto-sync | Blockchain Scanner. Stateless-сканер. Опрашивает внешние ноды, используя курсоры из БД. Работает в режиме Read-Only. | Async (Событийный) |
| sana-fx-engine | Currency Gateway. Агрегирует курсы валют из разных источников (Binance, ECB) и предоставляет их Ядру с минутной точностью (in-memory). | Real-time (Кэширующий) |
| sana-report-worker | Document Generator. Генерирует тяжелые PDF/Excel отчеты. Изолирован, чтобы утечка памяти при рендеринге не роняла API. | Queue-based (По запросу) |
| sana-tax-worker | Compliance Engine. Выполняет сложные налоговые расчеты (прогрессивные шкалы, специфические вычеты), которые трудно реализовать на PL/pgSQL. | On-demand (Вычисляемый) |

### 4. Фабрика Адаптеров (Interface Layer)

Чтобы бизнес-логика не зависела от внешних вендоров, Ядро использует слой абстракции (Rust Traits).

**AI Factory:** Позволяет переключаться между Gemini Flash (для быстрых ответов) и Claude Opus (для глубокой аналитики) на лету, просто меняя конфиг. Бэкенд не знает, какая модель отвечает, он работает с интерфейсом `ModelProvider`,.

**Crypto & FX Factory:** Реализует логику консенсуса. Адаптер может опросить три источника курсов и вернуть среднее значение, исключая манипуляции рынком,.

**Secret Injection:** Адаптеры получают API-ключи только в рантайме из HashiCorp Vault. В коде ключей нет,.

### 6. Потоки данных и Отказоустойчивость

**Sync Flow (Чат):** User -> Core -> AI -> Core -> DB -> Core -> User. Должен укладываться в <1000ms.

**Async Flow (Крипта/Отчеты):** Satellite -> RabbitMQ -> Core -> DB.

**Circuit Breaker:** Если внешний сервис (например, банк или LLM) начинает сбоить, Фабрика Адаптеров временно отключает его и переходит на резервный канал, не блокируя основной поток Ядра.

### Резюме

Архитектура **Sana Backend** — это система, где **Ядро** управляет, **Спутники** работают, **БД** хранит истину, а **Адаптеры** общаются с внешним миром. Такая структура обеспечивает высокую живучесть: даже если упадет модуль аналитики или отвалится провайдер курсов валют, пользователь по-прежнему сможет записать трату и получить текущий баланс.

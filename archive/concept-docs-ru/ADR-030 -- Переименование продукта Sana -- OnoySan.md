## 1. Решение

Продукт называется **OnoySan** (кириллица — **ОнойСан**). Имя Sana выводится из всех публичных поверхностей до регистрации юрлица и запуска когорты.

Дескриптор не меняется: **«Your financial friend» / «Твой финансовый друг»** (не «You're»).

## 2. Контекст: почему ушли от Sana

Кратко, подробности — в досье «Нейминг финансового друга».

- Sana совпадает с AI-брендом Workday по трём осям сразу: имя, AI-ассистент, финансы/управление деньгами. Workday закрыл покупку Sana Labs (~$1,1 млрд) 4 ноября 2025 года.
- В классе 9 МКТУ есть и другие знаки SANA.
- Выдача «Sana AI» занята Workday: органический трафик на этом имени недоступен.
- Риск смешения с владельцем, у которого крупный IP-отдел, неприемлем для продукта, который ещё не заплатил ни за один товарный знак.

Шортлист Saya / Moldi не был утверждён; финальным выбрано имя вне шортлиста — OnoySan.

## 3. Имя: смысл и звучание

**Корни (кыргызский):**

- **«оңой»** — лёгкий, простой, без усилия;
- **«сан»** — число, количество.

Вместе **«оңой сан» — «простое число», «лёгкая цифра»**. Имя буквально называет героя бренда: одну честную цифру дня, которую понять без усилия. Это прямой ответ сегменту «паника от незнания»: страшно не число, страшна неизвестность.

**Преемственность с Sana.** Корень «сан» — тот же, что в «сана» (сознание) и «санау» (считать). Смысловая линия «понять + посчитать» сохраняется, а капитал первого имени в голове основателя и ранних тестеров не теряется.

**Второй слой (желательный критерий №8).** Для англоязычного и международного уха «-san» читается как японское вежливое обращение: имя звучит как вежливо названный персонаж, а не как сервис. Это работает на архетип «Заботливый по форме» и на буквальность «друга».

**Произношение:** о-нОй-сАн, три слога, ударение на последний (по кыргызской норме). Для англоязычных допустимо «OH-noy-san» — это не ломает узнавание.

**Фильтр звучания «буба/кики»:** сонорные «н», «й», открытые «о», «а»; нет «з», «к», «т», «р». Проходит.

## 5. Канон написания

| Контекст | Форма | Правило |
| --- | --- | --- |
| Название бренда в тексте (en, fr) | **OnoySan** | Одно слово, две заглавные. Не «Onoy San», не «Onoysan», не «ONOY-SAN» |
| Название бренда в тексте (ru, ky) | **ОнойСан** | Одна форма для обоих языков. «ң» в имени не используется — иначе два написания |
| Обыгрывание смысла в кыргызском маркетинге | «оңой сан» | Только как фраза-объяснение, не как имя |
| Товарный знак | **ONOYSAN** | Словесный знак в стандартных символах: защищает любое написание и регистр |
| Домены, хендлы, идентификаторы | `onoysan` | Только строчные, без дефиса |
| Логотип | Словесный знак OnoySan + монограмма | Монограмма (вероятно, «O» или «OS») — для favicon 16 px и аватара Telegram 40 px; проверка по Branding §11 |

**Голосовая диктовка — главный риск канона.** На слух «OnoySan» легко записать как «Onoisan», «Onoy San», «Onoisun». Отсюда: защитный домен `onoisan.com` (§6) и тест диктовки на 5 людях с разными родными языками (критерий 4) — до печати чего-либо.

## 6. Домены

> **Допущение.** На момент ADR домены не зарегистрированы; по данным основателя все нужные зоны свободны в Cloudflare. Схема ниже — целевая. Поддержку каждой зоны Cloudflare Registrar нужно подтвердить при покупке: ccTLD Центральной Азии (.kg, .kz) Cloudflare, как правило, не продаёт — их берут у аккредитованного регистратора зоны.

### 6.1. Что регистрировать

| Приоритет | Домен | Роль | Почему |
| --- | --- | --- | --- |
| **P0** | `onoysan.com` | Основной: сайт, PWA, API, почта | Критерий №10; единственный домен, который диктуется без уточнений |
| **P0** | `onoysan.app` | Редирект на `.com`; запасной для deep links | Зона с обязательным HTTPS (HSTS preload); естественный адрес для приложения; дёшево закрывает очевидный сквот |
| **P0** | `onoisan.com` | Редирект на `onoysan.com` | Главная ошибка диктовки (y → i); фишинг на опечатке — прямой риск для финансового продукта |
| **P0** | `onoysan.dev` | Внутренний: staging, preview, внутренние панели | Изоляция cookie, CSP и репутации от прод-домена; сотрудник и пользователь никогда не видят staging на «настоящем» домене |
| P1 | `onoysan.kg` | Редирект; локальное доверие на домашнем рынке | Через регистратора зоны .kg |
| P1 | `onoysan.kz` | Редирект; второй рынок ЦА | Проверить требования зоны .kz к размещению DNS/серверов на территории Казахстана |
| P1 | `onoysan.ai` | Только защитная регистрация, редирект | Не использовать как основной: досье прямо запрещает привязывать бренд к слову «AI» |
| P2 | `onoysan.io`, `onoysan.co` | Защитные | Дёшево, если бюджет позволяет; не критично |
| P2 | `getonoysan.com` | Защитный | Приставка «get-» допускается критерием №10; занять, чтобы не заняли |

Не регистрируем: дефисные варианты (`onoy-san.com`), IDN-кириллицу, зоны вне целевых рынков — защитная ценность ниже стоимости продления.

### 6.2. Схема поддоменов `onoysan.com`

Отражает «Крепость в три кольца» (Architectural §4, §8): наружу торчит только кольцо 1.

| Поддомен | Назначение | Кольцо / компонент |
| --- | --- | --- |
| `onoysan.com` | Лендинг, правовые страницы (`/privacy`, `/terms`), `/.well-known/` | Публичный статический хостинг |
| `app.onoysan.com` | PWA: биллинг, Access Management, экспорт, удаление аккаунта, Consent Gate (Architectural §7) | Кольцо 1 → ядро |
| `api.onoysan.com` | Публичный API для клиентов | Кольцо 1: ALB + WAF → `*-core` |
| `hook.onoysan.com` | Webhook Telegram Bot API (и будущих каналов) | Отдельное имя: свой rate-limit, своё WAF-правило, проверка `secret_token` Telegram |
| `status.onoysan.com` | Статус-страница | Внешний сервис, вне инфраструктуры |
| `help.onoysan.com` | База знаний / поддержка | По мере появления |
| `send.onoysan.com` | Отправка транзакционной почты (коды входа, уведомления) | Отдельный поддомен для репутации отправителя; основной домен не страдает при проблемах с доставляемостью |

Внутренние имена (Vault, RabbitMQ, PostgreSQL, Redis) в публичный DNS не попадают вообще — только приватные зоны / `onoysan.dev`.

### 6.3. DNS и безопасность доменов (обязательно для всех, включая защитные)

- **Registrar lock** и 2FA (аппаратный ключ) на аккаунте Cloudflare; отдельный аккаунт-владелец, не личный.
- **DNSSEC** включён везде, где зона поддерживает.
- **CAA**-записи: выпуск сертификатов только у выбранных CA.
- **Почтовая защита от спуфинга** на каждом домене, который не отправляет почту (`onoysan.app`, `onoisan.com`, `.kg`, `.kz`, `.ai` и т. д.): `SPF v=spf1 -all`, `DMARC p=reject`, пустой MX (`0 .`). Для финансового продукта фишинг от имени бренда — сценарий №1.
- На `onoysan.com`: SPF + DKIM + DMARC с переходом `p=none → quarantine → reject` после мониторинга отчётов; MTA-STS и TLS-RPT.
- **HSTS** с `includeSubDomains` и заявкой в preload — после того как все поддомены работают по HTTPS.
- Автопродление на всех доменах; дата истечения — в календаре с напоминанием за 60 дней. Потеря основного домена — необратимая точка отказа.
- WHOIS privacy (у Cloudflare по умолчанию) — до подачи заявки на товарный знак имя не должно светиться как «новый проект Х».

## 9. Код-нейм `sana-*` в инфраструктуре

**Решение: переименовать до первого прод-деплоя.** Префикс — `onoy-` (короткий, но однозначный).

Почему не оставлять `sana-*` как код-нейм:

- сейчас переименование стоит почти ноль — прод-данных и внешних интеграций нет; после запуска это миграция ролей БД, GUC, очередей и дашбордов;
- «sana» в логах, ролях и репозитории — постоянное напоминание о бренде, от которого ушли из-за риска смешения с Workday; в любом публичном артефакте (open-source, вакансия, статья) это всплывёт;
- два словаря (бренд и код-нейм) в команде из одного человека — лишний когнитивный налог.

| Было | Стало |
| --- | --- |
| `sana-core`, `sana-fx-engine`, `sana-pulse`, `sana-nostradamus`, `sana-crypto-sync`, `sana-report-worker`, `sana-import-worker` | `onoy-core`, `onoy-fx-engine`, `onoy-pulse`, `onoy-nostradamus`, `onoy-crypto-sync`, `onoy-report-worker`, `onoy-import-worker` |
| Роли БД `sana_app`, `sana_worker_<name>`, `sana_readonly_ops`, `sana_purge` | `onoy_app`, `onoy_worker_<name>`, `onoy_readonly_ops`, `onoy_purge` |
| GUC `sana.user_id` (RLS, `auth.fn_my_spaces`) | `onoy.user_id` |
| `sana.os.yaml`, `schema: sana-os/1` | `onoysan.os.yaml`, `schema: onoysan-os/1` |

Схемы БД (`core`, `auth`, `analytics`, `system`) от имени не зависят и не меняются.

## 10. Риски и защита

| Риск | Вероятность | Защита |
| --- | --- | --- |
| **Knockout ≠ clearance.** Пустой веб-поиск и база не ловят фонетику и транслитерацию («Onoisan», «Онойсан», «Onoy») и незарегистрированное использование (common law в США) | Средняя | Пройти полный knockout по процессу из досье (USPTO tmsearch, TMview, WIPO GBD, Kazpatent, Кыргызпатент, сторы). Clearance у патентного поверенного не пропускается — до печати и платного маркетинга |
| **Потеря приоритета** между выбором имени и заявкой | Низкая, но необратимая | Заявка сразу после clearance: US intent-to-use 1(b) (пошлина $350 за класс, кл. 9, 36, 42) или Мадрид через Кыргызпатент |
| **Сквоттинг доменов и хендлов** после публичной заявки на ТЗ | Средняя | Отступаем от порядка досье («домены после заявки»): домены и хендлы — **сейчас**. Они стоят десятки долларов в год, а заявка USPTO публична и привлекает сквоттеров |
| **Ошибки диктовки** (Onoisan, Onoy San) | Высокая | Защитный `onoisan.com`, `@onoisan`; тест диктовки; в голосовой рекламе — произносить по буквам хотя бы раз |
| **Японский слой читается как аниме-эстетика** в англоязычной выдаче (поиск по «-san» забит персонажами) и как «культурная апроприация» | Средняя для SEO, низкая для репутации | Визуальное направление без японской стилизации; SEO на «OnoySan app / finance»; проверка восприятия на 2–3 англоязычных респондентах |
| **Негативные значения** в fr, kk, tr, el/ka | Неизвестна | Проверка у носителей каждого языка до clearance (критерий №6); пятый язык (el или ka, T-002) решить до проверки |
| **CamelCase не масштабируется** на 16 px | Высокая | Монограмма как обязательная часть системы знака |

## 12. Критерии пересмотра

ADR пересматривается, если выполняется хотя бы одно:

- clearance-заключение поверенного оценивает риск конфликта в кл. 9, 36 или 42 как средний или высокий;
- проверка у носителей находит негативное или комическое значение в любом из языков интерфейса;
- тест диктовки: ≥ 2 из 5 записывают имя неверно **и** защитный домен не перехватывает ошибку (вариант, отличный от `onoisan`).

Пересмотр до подачи заявки стоит только защитных доменов; после запуска — бренда целиком. Поэтому проверки §11 «до clearance» не откладываются.

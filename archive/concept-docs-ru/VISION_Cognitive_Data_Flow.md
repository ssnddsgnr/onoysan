# 1. Роль ИИ в архитектуре

В системе Sana Искусственный Интеллект (LLM) выполняет роль **переводчика**, а не калькулятора или хранилища.

**Задача ИИ:** Преобразовать естественный язык (хаос) в структурированный JSON (порядок) и наоборот.

**Ограничение:** ИИ запрещено выполнять арифметические операции (с этим справляется PostgreSQL) и принимать решения о записи в реестр без валидации Бэкендом.

# 2. Входящий поток (Ingestion Pipeline)

Процесс обработки данных от пользователя к базе данных.

#### 2.1. Санитизация (Обезличивание)

Перед отправкой данных во внешние модели (Gemini/Claude/Groq) Бэкенд выполняет очистку:

**PII Filter:** Удаляются номера телефонов, email и адреса, если они случайно попали в текст сообщения.

**Identity Strip:** Идентификатор пользователя (`internal_user_id`) никогда не передается в LLM. Модель работает в изолированном контексте текущей сессии без привязки к реальной личности.

**Name Injection:** Если требуется персонализация, используется только `encrypted_display_name` (например, «Алексей»), расшифрованное в оперативной памяти.

#### 2.2. Нормализация (Extraction)

Агент-Парсер получает очищенный текст/фото и преобразует его в машиночитаемый вид.

**Вход:** «Купил продукты на 2000 и еще 500 отдал за такси».

#### 2.3. Валидация и Буфер (Validation & Pending)

ИИ может ошибаться («галлюцинировать»). Поэтому полученный JSON не пишется сразу в `ledger_transactions`.

**Проверка Бэкендом:** Система проверяет, существуют ли указанные кошельки и категории.

**Pending Layer:** Данные сохраняются в таблицу `pending_layer` со статусом `pending`.

**Подтверждение:** Пользователь видит результат разбора. Только после нажатия кнопки «Да» или молчаливого согласия (в зависимости от настроек) данные переносятся в основной Леджер.

### 3. Исходящий поток (Egestion Pipeline)

Процесс формирования ответа от базы данных к пользователю.

#### 3.1. Получение фактов (Retrieval)

Дирижёр (Orchestrator) не спрашивает у LLM «сколько у меня денег?». Он делает запрос к базе данных.

**Query:** `SELECT safe_to_spend FROM user_snapshots WHERE id = ...`

**Result:** `540.50 USD`

**Context:** Эти цифры подаются на вход ИИ как непреложные факты (System Prompt Context).

#### 3.2. Интерпретация (Synthesis)

Агент-Консильери или Sana Zen получает цифры и контекст запроса.

**Вход:** `{ "safe_to_spend": 540.50, "goal_lag": -200, "tone": "supportive" }`

**Генерация:** ИИ оборачивает данные в текст, соответствующий настроению и стилю общения.

**Выход:** «Доступно 540.Мынемногоотстаемотцели(−200), поэтому крупные покупки лучше отложить».

### 5. Контекстная память

ИИ не помнит всё подряд. Контекст ограничен технически:

**Session Scope:** В рамках одной сессии (`chat_sessions`) ИИ помнит последние N сообщений для поддержания диалога.

**Entity Binding:** Если диалог привязан к проекту, ИИ «видит» только транзакции этого проекта, игнорируя личные траты. Это снижает риск утечки контекста и галлюцинаций.

### Резюме

ИИ в Sana — это слой абстракции интерфейса.

**Вход:** User Language → **AI** → JSON → DB.

**Выход:** DB Data → JSON → **AI** → User Language. Математика, балансы и история хранятся и обрабатываются строго в PostgreSQL.

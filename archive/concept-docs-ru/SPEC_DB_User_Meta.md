**Статус:** Final Technical Specification

**Слой:** Identity & Sovereignty (Идентификация и Суверенитет)

**Описание:** Таблицы этого слоя отвечают за аутентификацию, хранение пользовательских настроек и управление правами доступа (Shared Sovereignty). Они изолированы от финансового ядра (Ledger), чтобы обеспечить максимальную приватность,.


--------------------------------------------------------------------------------

# 1. Таблица: `auth_identities` (Gateway)

**Назначение:** Единственный шлюз входа в систему. Реализует концепцию **Identity Split**: внешние идентификаторы (Telegram ID, Email) хранятся здесь и мапятся на анонимный `internal_user_id`, который используется во всей остальной системе. Финансовое ядро никогда не знает вашего Telegram ID,.

| Поле | Тип данных | Описание и Инварианты |
| --- | --- | --- |
| id | UUID | PK. Уникальный идентификатор записи авторизации. |
| internal_user_id | UUID | Master Key. Единый анонимный ID пользователя. Ссылка 1:N (один юзер может иметь несколько методов входа). |
| provider_type | VARCHAR(50) | Тип провайдера: telegram, email, apple_id. |
| external_id | VARCHAR(255) | ID во внешней системе (напр. Telegram ID). Строго конфиденциально: никогда не передается в LLM,. |
| identity_hash | VARCHAR(255) | Хэш внешнего ID для безопасной сверки без хранения открытых данных. |
| created_at | TIMESTAMPTZ | Дата привязки метода входа. |
| last_seen_at | TIMESTAMPTZ | Время последней активности (используется для TTL сессий). |
| status | VARCHAR(20) | active, blocked, deleted. Позволяет мгновенно отозвать доступ. |
| provider_metadata | JSONB | Кэш публичных данных (никнейм, имя, ссылка на аватар) для отображения в UI приветствия. |

`UNIQUE (provider_type, external_id)` — защита от дублей регистраций.

`INDEX (internal_user_id)` — быстрый поиск всех методов входа для конкретного пользователя.


--------------------------------------------------------------------------------

# 2. Таблица: `users_metadata` (Encrypted Profile)

**Назначение:** Хранилище персональных настроек и профиля. Эти данные отделены от транзакций, чтобы в случае анализа Ledger невозможно было понять, кому принадлежат деньги, без доступа к этой таблице.

| Поле | Тип данных | Описание и Инварианты |
| --- | --- | --- |
| internal_user_id | UUID | PK. Связь 1:1 с auth_identities. |
| encrypted_display_name | TEXT | Зашифрованное имя для обращения ИИ (Zero-Knowledge). Расшифровывается только в момент генерации ответа. |
| encrypted_legal_name | TEXT | Опционально. Полное юридическое имя (для генерации инвойсов). |
| timezone | VARCHAR(50) | Часовой пояс. Критически важен для работы модуля Nostradamus и закрытия дня (EOD). |
| base_currency | VARCHAR(10) | FIX: Основная валюта отчетности (напр. USD, EUR, USDT). В этой валюте считаются снапшоты Net Worth. |
| language_code | VARCHAR(5) | Код языка по ISO 639-1 (ru, en, ky). Первичный источник для локализации интерфейса. |
| is_language_manual | BOOLEAN | true — язык выбран вручную пользователем (жесткая фиксация), false — автоопределение. |
| ui_preferences | JSONB | Настройки темы, формата дат, скрытия балансов (Blur mode). |
| ai_settings | JSONB | Настройки личности ИИ (тон голоса, уровень детализации, "ты/вы"). |
| onboarding_status | VARCHAR(50) | Текущий шаг обучения пользователя (например, wallet_added, first_transaction). |
| updated_at | TIMESTAMPTZ | Время последнего изменения настроек. |

**Encryption at Rest:** Поля `encrypted_*` хранятся в зашифрованном виде. Ключи шифрования управляются отдельным сервисом (Vault).

# 3. Таблица: `access_grants` (Shared Sovereignty)

**Назначение:** Реализация **RBAC** (Role-Based Access Control). Позволяет пользователям предоставлять доступ к своим финансовым сущностям (кошелькам, проектам) другим людям без передачи паролей,.

| Поле | Тип данных | Описание и Инварианты |
| --- | --- | --- |
| id | UUID | PK. Уникальный ID гранта. |
| internal_user_id | UUID | PK (Composite). Владелец ресурса (Grantor), кто выдал права. |
| grantee_identity_id | UUID | Ссылка на auth_identities.id того, кому выдан доступ (Grantee). |
| resource_type | VARCHAR(20) | Тип ресурса: wallet, project, envelope. |
| resource_id | UUID | ID конкретного ресурса (например, wallet_id семейной карты). |
| role | VARCHAR(20) | Роль доступа: viewer (просмотр), editor (запись), requester (запрос средств), manager (управление). |
| expires_at | TIMESTAMPTZ | Дата истечения прав (для временного доступа). Если NULL — доступ бессрочный. |
| created_at | TIMESTAMPTZ | Дата выдачи прав. |

**Row Level Security (RLS):** Все запросы к финансовым таблицам (`wallets`, `ledger`) автоматически фильтруются через эту таблицу. Пользователь видит только свои ресурсы ИЛИ ресурсы, где он есть в `access_grants`.

**Zero-Trust:** Делегат с ролью `editor` может создавать записи в Ledger, но поле `created_by` в транзакции будет указывать на него, обеспечивая полный аудит действий.

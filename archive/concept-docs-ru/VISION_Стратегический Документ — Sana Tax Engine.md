# VISION_Стратегический Документ — Sana Tax Engine

Этот документ описывает **Tax Engine** — один из самых критически важных модулей Sana. Его задача — превратить сложную налоговую отчетность в невидимый фоновый процесс, гарантируя, что пользователь всегда видит только свои «реальные» деньги.

Цель: Автоматическое выделение и резервирование налоговых обязательств в режиме реального времени.

Принцип: «Налоги — это не твои деньги». Система блокирует их до момента уплаты.


--------------------------------------------------------------------------------

# 1. Архитектурные режимы налогообложения

Tax Engine поддерживает три фундаментальных сценария, которые переключаются в настройках конкретного счёт привязанного к бизнес-профилю или кошельку.

## Режим А: Налог с оборота (Revenue-based)

**Ца:** Самозанятые, фрилансеры (УСН 6%, ПСН).

**Логика:** Налог рассчитывается мгновенно при любом входящем потоке на физический счет.

**Формула:**

Taxreserve​=Incomegross​×Ratetax​

**Действие:** При зачислении $1000 при ставке 6%, система сразу переводит $60 в виртуальный конверт «Налоги». Пользователь видит доступный остаток $940.

## Режим Б: Налог с прибыли (Profit-based)

**Ца:** Малый бизнес (УСН «Доходы минус расходы»), трейдеры.

**Логика:** Налог рассчитывается как дельта между доходами и расходами, помеченными как «бизнес-затраты».

**Формула:**

Taxreserve​=(Incometotal​−Expensedeductible​)×Ratetax​

**Действие:** Система ведет накопительный итог налоговой базы. При каждом расходе, подтвержденном как «вычитаемый», налоговое обязательство в конверте уменьшается автоматически.

## Режим В: Косвенные налоги (VAT / НДС)

**Ца:** Компании, работающие с НДС/Sales Tax.

**Логика:** Сумма налога отделяется от выручки в момент транзакции.

**Действие:** При оплате счета на $1200 (где $200 — НДС), система физически видит $1200 на счету, но в «Мире Смыслов» распределяет: $1000 в доход, $200 — в транзитный конверт НДС.


--------------------------------------------------------------------------------

# 2. Математические инварианты Tax Engine

Чтобы исключить кассовые разрывы из-за налогов, БД соблюдает следующие правила:

**Приоритет №1:** Налоговый триггер срабатывает раньше любых других распределений по целям (фондам).

**Запрет овердрафта:** Налоговый конверт не может быть использован для покрытия других трат. Он «заперт» (Locked State).

**Синхронизация с реальностью:** При уплате налога в реальном мире (платеж в бюджет), Sana списывает сумму именно из налогового конверта, обнуляя обязательство.


--------------------------------------------------------------------------------

# 3. Структура управления (Tax Rules Table)

В БД создается таблица `tax_rules`, где хранятся «рецепты» для каждого пользователя.

| Поле | Описание | Пример |
| --- | --- | --- |
| target_wallet_id | К какому счету привязано правило | wallet_kaspi_business |
| tax_mode | Тип режима (A, B, или В) | revenue_based |
| rate | Процентная ставка | 0.06 |
| deductible_categories | Массив категорий, уменьшающих базу (для режима Б) | ['rent', 'software', 'cloud'] |
| auto_reserve | Автоматически ли переводить в конверт | true |


--------------------------------------------------------------------------------

# 4. Логика работы (Step-by-Step)

**Событие:** На счет пользователя поступает $100.

**Backend:** Видит входящий `intent: income`.

**Tax Engine:** Проверяет `tax_rules` для этого счета.

**Расчет:** Видит Режим А (6%). Считает: $6.

**Транзакция:** Создает запись в Ledger:`Wallets` (реальность): +$100.`Envelope: Income` (смыслы): +$94.`Envelope: Tax Reserve` (смыслы): +$6.

`Wallets` (реальность): +$100.

`Envelope: Income` (смыслы): +$94.

`Envelope: Tax Reserve` (смыслы): +$6.

**Ответ:** AI-Ассистент говорит: *"Пришли 100*.Яужеотложил6* на налоги, твой чистый доход — 94$"*.


--------------------------------------------------------------------------------

# 5. Взаимодействие с Агентами

**Нормализатор:** При анализе чека помечает, включен ли в него налог (НДС).

**Консильери:** На вопрос «Сколько у меня денег?» всегда отвечает суммой **за вычетом** налоговых резервов (Net Cash).

**Нострадамус:** При прогнозировании кассового разрыва учитывает дату ближайшего налогового платежа как «неизбежное событие».

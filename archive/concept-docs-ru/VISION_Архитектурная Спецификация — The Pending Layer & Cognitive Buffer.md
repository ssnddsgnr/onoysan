# VISION_Архитектурная Спецификация — The Pending Layer & Cognitive Buffer

Этот документ описывает **Pending Layer** (Слой ожидания) — критически важный буферный механизм Sana, который позволяет системе обрабатывать асинхронные события, не перегружая когнитивный ресурс пользователя. Это «интеллектуальный зал ожидания» для данных, которые еще не стали частью детерминированного Ledger.


--------------------------------------------------------------------------------

Статус: Final Specification

Роль: Буфер асинхронных событий и незавершенных интентов.

Цель: Устранение «спама» от системы и структурирование неопределенности.


--------------------------------------------------------------------------------

# 1. Концепция: Управление неопределенностью

В Sana ни одно событие не должно быть потеряно, но и ни одно событие не должно прерывать жизнь пользователя без веской причины. **Pending Layer** — это слой, где хранятся события, которые уже зафиксированы системой, но еще не получили финального «смысла» от пользователя (Оракула).

## Что попадает в Pending Layer:

**Неполные транзакции:** Записи, где ИИ-Нормализатор не смог однозначно определить кошелек, конверт или проект.

**Асинхронные крипто-события:** Новые транзакции, обнаруженные `sana-crypto-sync` на кошельках пользователя, но не имеющие контекста (например, входящий перевод без описания).

**Прогнозы Nostradamus:** Предиктивные события (кассовые разрывы, отклонения от целей), которые требуют подтверждения или выбора решения.

**Подвисшие вопросы:** Уточнения от Дирижёра, на которые пользователь не ответил в моменте.


--------------------------------------------------------------------------------

# 2. Атрибуты записи: Контекст и Приоритет

Каждая единица информации в слое ожидания обладает набором метаданных, которые определяют её «судьбу».

## **1. Контекст (Context Payload):**

Полный снимок данных на момент возникновения (сырой JSON от Backend, транскрипция аудио, скриншот чека).

## **2. Приоритет (Urgency Score):**

**Low:** Незначительное расхождение баланса, мелкая трата без категории.

**Medium:** Нераспознанный доход, приближающаяся цель без пополнения.

**High:** Критический кассовый разрыв через 3 дня, подозрительная активность на счету.

## **3. TTL (Time To Live):**

Срок актуальности запроса.


--------------------------------------------------------------------------------

# 3. Политика «Anti-Spam»: Тишина как стандарт

Sana не беспокоит пользователя по пустякам. Pending Layer работает как фильтр:

**Группировка (Batching):** Вместо пяти уведомлений о пяти разных крипто-транзакциях, система накапливает их в Pending-слое и формирует один отчет: *«У тебя 5 новых поступлений в крипте. Давай распределим их по проектам?»*.

**Адаптивная частота:** Система анализирует график пользователя. Если приоритет записи `Low`, она будет ждать «тихого часа» или еженедельного отчета в Outbox.

**Мгновенный триггер:** Только записи с приоритетом `High` имеют право инициировать немедленное пуш-уведомление через Дирижёра.


--------------------------------------------------------------------------------

# 4. Интеграция с Backend и AI-слоем

## **1. Discovery:**

Спутник (например, `crypto-sync`) находит транзакцию в блокчейне.

## **2. Drafting:**

Backend создает в БД запись в таблице `pending_events` (а не в `ledger`).

## **3. Enrichment:**

AI-Дирижёр пытается сам достроить смысл на основе истории. Если не получается — ставит статус `Unresolved`.

## **4. Resolution:**

Сервис отправляет сообщение о том, что есть зависшие слои.

Консильери подтягивает данные из Pending Layer и формирует сообщение.

После ответа пользователя Backend переносит данные из `pending_events` в финальный `ledger`, соблюдая все инварианты.


--------------------------------------------------------------------------------

## 5. Форматы вывода (Reporting)

Pending Layer позволяет генерировать два типа отчетов:

**Точечный инсайт:** Сообщение по конкретному важному пункту (например, уточнение по крупному авансу).

**Дайджест (The Cleanup Report):** Полный список «хвостов». Идеально для конца недели. Пользователь может пройтись по списку и за пару минут закрыть все вопросы короткими ответами («Это на еду», «Это проект Б», «Это ошибка, игнорируй»).


--------------------------------------------------------------------------------

# Почему это важно:

Pending Layer превращает Sana в **деликатного помощника**. Система не выглядит как «глючный бот», который заваливает вопросами, а как профессиональный ассистент, который собирает все неясности в папку «На подпись» и приносит её в самый удобный момент.

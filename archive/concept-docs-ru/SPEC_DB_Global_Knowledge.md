Подробная спецификация слоя глобальных знаний. Этот документ определяет статические и динамические справочники, которые служат фундаментом для работы ИИ (классификация) и математического ядра (оценка стоимости активов).


--------------------------------------------------------------------------------

**Концепция:** Global Knowledge Registry (Реестр Глобальных Знаний) **Схема БД:** `system` (отдельная схема, доступная `public` только на чтение) **Назначение:** Обеспечение единых стандартов классификации, оценки стоимости и обогащения данных для всех пользователей системы.


--------------------------------------------------------------------------------

# 1. Валютный Движок (Minute-Precision FX)

Sana реализует концепцию **«Заморозки времени»**. Любая транзакция навсегда привязывается к курсу валют той минуты, когда она произошла. Для этого используется глобальная таблица истории курсов с механизмом агрегации (Rollup).

## 1.1. Таблица: `system.fx_rates_history`

Хранит котировки фиатных валют, криптовалют и металлов.

| Поле | Тип данных | Описание и Инварианты |
| --- | --- | --- |
| pair_hash | TEXT | Part of PK. Хэш пары (напр., USD_BTC, EUR_KGS). Ускоряет поиск и индексацию. |
| fetched_at | TIMESTAMPTZ | Part of PK. Точное время фиксации курса. |
| resolution | VARCHAR(10) | Масштаб данных: 1m (минуты), 1h (часы), 1d (дни). |
| base_currency | VARCHAR(10) | Исходная валюта (напр., USD). |
| target_currency | VARCHAR(10) | Валюта котировки (напр., BTC, ETH). |
| rate_avg | NUMERIC | Средневзвешенный курс за период (Open+Close+High+Low / 4). Используется для аналитики. |
| rate_last | NUMERIC | Курс закрытия периода. Именно это значение копируется в ledger_transactions при записи транзакции. |
| provider_slug | VARCHAR(50) | Источник данных (binance, chainlink, ecb). Обеспечивает принцип Provider Agnostic. |
| is_verified | BOOLEAN | true, если курс подтвержден консенсусом минимум двух независимых источников (защита от сбоев оракула). |

## 1.2. Политика хранения и свертки (Rollup Policy)

Чтобы база данных не разрасталась бесконечно, применяется стратегия прореживания данных (Retention Policy),:

**Hot Data (1m):** Хранятся поминутные данные за последние **24 часа**. Используются для мгновенной конвертации текущих операций.

**Warm Data (1h):** Данные старше 24 часов агрегируются в часовые свечи (среднее за час + курс закрытия). Хранятся **30 дней**.

**Cold Data (1d):** Данные старше 30 дней агрегируются в дневные свечи (курс закрытия дня). Хранятся **вечно**.

**Инвариант:** Удаление детальных данных (1m) происходит только после успешного создания агрегированной записи (1h).

## 2. Глобальная Таксономия (Categories Taxonomy)

В отличие от большинства приложений, где пользователь создает категории хаотично, Sana использует жесткую **иерархическую таксономию**. Это необходимо для корректной работы ИИ: нейросеть должна знать эталонные смыслы («Еда», «Транспорт»), чтобы правильно классифицировать траты миллионов пользователей.

### 2.1. Таблица: `system.categories_dictionary`

Эталонный справочник. Пользователи не могут удалять записи отсюда, но могут ссылаться на них.

| Поле | Тип данных | Описание и Инварианты |
| --- | --- | --- |
| slug | VARCHAR(100) | PK. Уникальный семантический код (напр., food_grocery, transport_taxi). |
| parent_slug | VARCHAR(100) | Ссылка на родителя (FK Self-reference). Создает дерево категорий (Food -> Restaurants). |
| display_name | JSONB | Локализованные названия для UI ({"en": "Groceries", "ru": "Продукты", "ky": "Азык-түлүк"}). |
| icon_emoji | VARCHAR(10) | Эмодзи для визуализации в чатах и дашбордах (🛒, 🚕). |
| is_system | BOOLEAN | Защита от модификаций. Системные категории (Transfer, Adjustment, Tax) неизменяемы. |
| ai_description | TEXT | Описание смысла категории для промптов LLM (напр., «Траты на продукты питания для дома, не рестораны»). |

### 2.2. Взаимодействие с Пользовательскими Тегами

Таксономия отвечает на вопрос «Что это глобально?». Для личной специфики используются теги (`tags_metadata`), которые накладываются поверх категорий.

**Пример:** Транзакция имеет категорию `travel_hotel` (системная), но пользователь добавляет тег `#trip_bali_2026` (личный).

# 3. Профили Мерчантов (Context Intelligence)

Глобальная база знаний о торговых точках, брендах и сервисах. Позволяет ИИ «узнавать» место покупки по сырому тексту из SMS или чека и автоматически предлагать категорию.

### 3.1. Таблица: `system.merchant_profiles`

| Поле | Тип данных | Описание и Инварианты |
| --- | --- | --- |
| id | UUID | PK. Уникальный ID профиля. |
| name | VARCHAR(255) | Эталонное имя бренда (Starbucks, Netflix, Uber). |
| match_patterns | JSONB | Массив regex-паттернов или ключевых слов для парсера (["uber trip", "uber*eat", "yandex.taxi"]). |
| default_category_slug | VARCHAR(100) | FK -> categories_dictionary. Категория по умолчанию (Uber -> transport_taxi). |
| brand_logo_url | VARCHAR | Ссылка на логотип для красивого отображения в ленте транзакций. |
| website | VARCHAR | Ссылка на сайт сервиса (для обогащения данных подписок). |
| is_subscription | BOOLEAN | Флаг, указывающий, что этот мерчант часто является подпиской (Netflix, Spotify). Сигнал для Nostradamus искать регулярность. |

## 3.2. Логика ИИ-обогащения

Когда пользователь присылает фото чека или текст «Uber 500»:

**Парсер** извлекает сырое имя: "Uber Trip KGS".

**Бэкенд** ищет совпадение в `merchant_profiles` по `match_patterns`.

Если найдено:В транзакцию подставляется чистое имя "Uber".Автоматически присваивается категория `transport_taxi`.В UI отображается логотип Uber.

В транзакцию подставляется чистое имя "Uber".

Автоматически присваивается категория `transport_taxi`.

В UI отображается логотип Uber.

Если не найдено: транзакция сохраняется с сырым именем, а запись отправляется в очередь на анализ для пополнения справочника.

# 4. Служебные типы данных (Custom Types)

Для обеспечения строгости данных на уровне схемы используются ENUM-типы PostgreSQL.

## 4.1. `enum_transaction_kind`

Определяет механику влияния на баланс:

`income` — Доход (увеличивает Wallet, требует распределения в Envelope).

`expense` — Расход (уменьшает Wallet и Envelope).

**transfer** — Перевод между своими счетами (не влияет на Net Worth).

**adjustment** — Корректировка баланса (Reality Sync).

**tax_reservation** — Виртуальное движение внутри Envelopes (блокировка налога).

## 4.2. `enum_wallet_type`

Помогает ИИ понимать контекст безопасности:

`fiat_bank` — Банковский счет.

`crypto_wallet` — Некастодиальный кошелек.

`exchange_account` — Аккаунт на бирже.

`cash` — Наличные.

## Резюме слоя

Слой `system` является **Read-Only** для обычных пользователей и ИИ-агентов. Он обеспечивает:

**Семантическую чистоту:** Все пользователи называют «Еду» одинаково (`food`), что позволяет строить глобальную аналитику.

**Финансовую точность:** Все транзакции оцениваются по единым историческим курсам.

**Магию UX:** Автоматическое распознавание брендов и категорий снижает когнитивную нагрузку ввода.

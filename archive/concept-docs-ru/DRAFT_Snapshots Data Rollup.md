# Draft_Snapshots Data Rollup

Ниже представлен проект регламента и структуры данных для системы многоуровневого хранения снапшотов (FX-курсов и финансовых показателей пользователя).

Эта стратегия обеспечивает высокую точность для текущих операций и компактность базы данных для многолетней истории.


--------------------------------------------------------------------------------

# 1. Слой Валютных Снапшотов (FX & Crypto Rates)

Для обеспечения «Minute-Precision FX» и эффективного хранения мы используем таблицу истории курсов с механизмом «затухания» (Rollup).

## 1.1. Структура таблицы: `fx_rates_history`

Эта таблица хранит данные во всех временных масштабах. Масштаб определяется полем `resolution`.

| Поле | Тип | Описание |
| --- | --- | --- |
| pair_hash | text (PK) | Хэш пары (например, USD_BTC). |
| fetched_at | timestamp (PK) | Время фиксации курса. |
| resolution | text | Масштаб: 1m, 1h, 1d. |
| rate_avg | numeric | Средний курс за период (арифметическое среднее). |
| rate_last | numeric | Последний зафиксированный курс на момент закрытия периода. |
| base_currency | text | Исходная валюта (например, USD). |
| target_currency | text | Валюта котировки (например, BTC). |

## 1.2. Регламент агрегации (Rollup Policy)

Процесс «схлопывания» выполняется фоновым воркером по следующему графику:

### **1. Из Минут в Часы (Hourly Rollup):**

**Когда:** Каждый час для данных старше 24 часов.

**Логика:** Берем все записи `1m` за час.

**Данные:** Вычисляем среднее N∑rate​ и берем `rate` самой последней минутной свечи часа.

### **2. Из Часов в Дни (Daily Rollup):**

**Когда:** Раз в сутки для данных старше 30 дней.

**Логика:** Агрегируем 24 записи `1h` в одну запись `1d`.

**Данные:** Среднее за сутки и финальный курс на 23:59:59.

### **3. Очистка (Pruning):**

После успешного создания часового снапшота минутные записи удаляются.

После создания дневного — удаляются часовые.

# 2. Слой Финансовых Снапшотов (User Analytics)

Помимо курсов, система хранит агрегированные состояния пользователя. Это позволяет ИИ мгновенно отвечать на вопросы без анализа всего реестра `ledger_transactions`.

## 2.1. Оперативный снапшот: `user_snapshots`

Обновляется **триггером** в реальном времени при каждой транзакции.

**Назначение:** Единое окно для ИИ-агентов.

**Ключевые показатели:** Net Worth (общий капитал), Safe-to-Spend (безопасный остаток), налоговые резервы и P&L проектов.

**Формат:** Хранит только **актуальное** состояние в одной строке на пользователя.

## 2.2. Исторические снапшоты баланса: `balance_snapshots_history`

В отличие от оперативного, этот слой сохраняет историю изменения состояния.

**Частота:** Запись создается раз в сутки (EOD — End of Day).

**Состав данных:**`total_balance_base`: Общая сумма во всех кошельках (Wallets) в базовой валюте.`total_obligations_net`: Чистая разница между тем, что должны нам, и тем, что должны мы.`snapshot_data`: JSONB-слепок всех балансов конвертов и счетов на конец дня.

`total_balance_base`: Общая сумма во всех кошельках (Wallets) в базовой валюте.

`total_obligations_net`: Чистая разница между тем, что должны нам, и тем, что должны мы.

`snapshot_data`: JSONB-слепок всех балансов конвертов и счетов на конец дня.

# 3. Интеграция с Крипто-движком

Поскольку ваш движок сам парсит сеть и записывает транзакции, система снапшотов взаимодействует с ним следующим образом:

**Поток данных:** Движок поставляет `tx_hash` и параметры транзакции.

**Фиксация курса:** В момент подтверждения транзакции система обращается к `fx_rates_history`, берет самый свежий курс `rate_last` и навсегда записывает его в поле `fx_rate_snapshot` таблицы Ledger.

**Синхронизация:** Снапшот пользователя (`user_snapshots`) обновляется автоматически после того, как движок внесет запись в реестр.

**Статус:** Core Specification

**Роль:** Управляемый канал административной коммуникации.

**Принцип:** «Информирование без прерывания финансового контекста».


--------------------------------------------------------------------------------

# 1. Цель и назначение

**System Broadcast Service** предназначен для оперативного информирования пользователей о событиях платформы, не требующих «Минимального волевого акта» или подтверждения транзакций. В отличие от `pending_layer`, этот слой работает в информационном поле и не влияет на математическую целостность Ledger.

**Примеры использования:**

Уведомления о технических работах и шардировании базы.

Объявления о выходе новых версий приложения (например, под iOS).

Экстренные оповещения о критических сбоях (Alerts).


--------------------------------------------------------------------------------

# 2. Структура данных: `system_announcements`

Таблица хранится в **Public/System Layer** и управляется через административный интерфейс бэкенда.

| Поле | Тип | Описание |
| --- | --- | --- |
| id | UUID | Первичный ключ. |
| title | VARCHAR | Краткий заголовок объявления. |
| content | TEXT | Полный текст сообщения. |
| type | VARCHAR | Категория: maintenance, release, info, alert. |
| target_group | JSONB | Фильтры получателей (например, {"os": "ios"} или {"geo": "KG"}). Позволяет таргетировать сообщения. |
| starts_at | TIMESTAMP | Время активации показа. |
| expires_at | TIMESTAMP | Время автоматического удаления из активного пула (TTL). |
| is_critical | BOOLEAN | Если true, сообщение отображается поверх основного интерфейса чата. |


--------------------------------------------------------------------------------

# 3. Механика интеграции и отображения

## 3.1. Визуализация в чате

Объявления доставляются пользователю через существующую таблицу **chat_messages**.

**Роль (Role):** Сообщения записываются со значением `system`.

**Тип контента (Content Type):** Используется значение `system_event`.

**Поток данных:** При инициализации `chat_sessions` бэкенд проверяет наличие активных записей в `system_announcements`, соответствующих `internal_user_id` и его группе, после чего «впрыскивает» их в ленту сообщений.

## 3.2. Контекст для ИИ-агентов

Дирижёр имеет доступ к активным системным объявлениям при формировании промпта для Агентов.

Если в системе активно объявление о техработах, ИИ-агент (например, Sana Zen) учитывает это в своих ответах на вопросы о задержках или ошибках синхронизации.


--------------------------------------------------------------------------------

# 4. Безопасность и администрирование

**RBAC:** Создание, редактирование и удаление объявлений доступно только пользователям с уровнем прав `admin`, зафиксированным в таблице **access_grants**.

**Audit Trail:** Каждое создание объявления фиксируется в **system_audit_logs** с указанием ID администратора и параметров таргетинга.

**Data Lifecycle:** Система строго соблюдает `expires_at`. После истечения срока актуальности объявление либо архивируется, либо удаляется согласно политике эфемерности бэклога.


--------------------------------------------------------------------------------

# Итог:

Слой System Broadcast Service отделяет операционные уведомления от финансовых транзакций, обеспечивая чистоту pending_layer и предоставляя ИИ-агентам дополнительный контекст о состоянии платформы.

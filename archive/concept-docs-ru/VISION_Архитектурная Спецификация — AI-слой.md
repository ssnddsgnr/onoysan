# VISION_Архитектурная Спецификация — AI-слой

В Sana AI-слой не является монолитом. Это динамическая среда, где сообщения трансформируются из хаоса естественного языка в строгую структуру и обратно.


--------------------------------------------------------------------------------

# 1. AI-Дирижёр (The Intent Orchestrator)

Дирижёр — это «центральный коммутатор» системы. Он обладает самым широким контекстом и отвечает за маршрутизацию смыслов.

## **Входные сигналы:**

Сообщения от Пользователя (текст, голос, фото, документ).

Сырые данные от Backend (JSON-ответы базы данных).

Статусы выполнения от Специализированных агентов.

## **Функции:**

**Intent Recognition (Определение намерений):** Понимает, что хочет пользователь: совершить транзакцию, получить прогноз, изменить права доступа или просто спросить «сколько денег?».

**Context Management:** Удерживает нить разговора, для этого у него есть — история чата и информация из DB, которую он может получить по запросу в backend.

**Routing:** Выбирает наиболее подходящего агента для текущей задачи.

**Conflict Resolution:** Если действия разных агентов противоречат друг другу, Дирижёр запрашивает уточнение у пользователя.


--------------------------------------------------------------------------------

# 2. Специализированные AI-агенты

Агенты — это узкопрофильные «переводчики», работающие на границе между человеческим смыслом и машинным кодом.

## А. Слой Интерпретации: Agent → Backend (The Scribe / Normalizer)

Этот слой агентов отвечает за «запись» реальности в систему. Его задача — превратить нечеткое человеческое сообщение в валидный JSON для Backend.

### **Процесс:**

Получает от Дирижёра сырое сообщение: *«Закинул 500 баксов на крипто-кошелёк Ledger, это на отпуск»*.

**Интерпретация:** Определяет сумму (500), валюту (USD), Wallet (Ledger), Конверт (Отпуск).

**Формирование структуры:** Генерирует JSON-объект. Может формировать несколько интентов из сложных сообщений.

**Выход:** Отправляет данные в Backend для валидации (проверка баланса, прав доступа) и записи в DB.

## Б. Слой Коммуникации: Backend → Agent (The Consigliere / Interpreter)

Этот слой агентов отвечает за «голос» системы. Его задача — оживить сухие цифры и сделать их понятными и полезными для пользователя.

### **Процесс:**

Получает от Дирижёра сырые JSON от Backend: `{"status": "success", "balance": 1200, "limit_reached": false, "projection": "safe"}`.

**Интерпретация:** Анализирует данные в контексте текущей ситуации пользователя.

**Генерация ответа:** Превращает JSON в естественный язык: *«Готово! Теперь в конверте "Отпуск" 1200$. С таким темпом накоплений ты достигнешь цели на две недели раньше плана»*.

**Выход:** Передает текст Дирижёру для отправки пользователю.


--------------------------------------------------------------------------------

# 3. Синергия и Безопасность

**Изоляция ролей:** Агент-переводчик (в Backend) не имеет права «придумывать» цифры. Он может только переводить то, что прислал Backend. Это исключает галлюцинации в финансовых отчетах.

**Backend-валидация:** Ни одно сообщение от Агента не попадает в базу данных напрямую. Backend всегда выступает «цензором», проверяя математическую корректность присланного JSON.

**Динамический выбор модели:** Дирижёр может использовать **Gemini 1.5 Flash** для быстрой интерпретации простых трат (Fast Loop) и **Gemini 1.5 Pro** для сложной аналитики (Slow Loop).


--------------------------------------------------------------------------------

# Вклад в детерминированность:

Такое разделение позволяет нам менять «голос» (Consigliere) или «зрение» (Normalizer) системы, не затрагивая ядро (Backend) и логику выбора (Дирижёр).

# Слой: 1. Physical & Logical State (Баланс и Контекст)

**Описание:** Этот слой обеспечивает фундаментальное уравнение системы: ∑Wallets≡∑Envelopes. Таблицы здесь описывают статические сущности (счета, цели, имущество), на которые ссылается динамический Ledger.

## 1.1. Таблица: `wallets` (Physical Layer)

**Назначение:** Иерархическая структура физических счетов. Реализует концепцию **Parent/Child Mirror**, чтобы устранить когнитивный шум (например, «MetaMask» — это родитель, а «ETH» и «USDT» внутри него — дети).

| Поле | Тип данных | Описание и Инварианты |
| --- | --- | --- |
| id | UUID | Part of PK. Уникальный ID счета. |
| internal_user_id | UUID | Part of PK. Владелец счета. Обеспечивает RLS. |
| parent_id | UUID (FK) | Ссылка на родителя. NULL = Контейнер (Биржа/Банк). NOT NULL = Конкретный актив (BTC, USD). |
| name | VARCHAR(100) | Название (MetaMask, Kaspi Gold, Наличные). |
| wallet_type | VARCHAR(50) | physical_device, crypto_software, exchange, fiat_bank, cash. Помогает ИИ понимать контекст безопасности (где нужны ключи, а где логин). |
| currency_code | VARCHAR(10) | FIX: Код валюты (USD, KGS, USDT, BTC). Расширено для стейблкоинов. Для родительских контейнеров может быть системным маркером MULTI. |
| is_working_capital | BOOLEAN | ADD: Флаг: true = средства учитываются в расчете Safe-to-Spend (ликвидные на жизнь); false = инвестиции/холд (не учитывать в ежедневных тратах). |
| is_system_account | BOOLEAN | Флаг «General Ledger». Используется для корректировок (Reality Sync) и заполнения пробелов в знании. |
| is_active | BOOLEAN | Флаг активности (soft delete). Позволяет архивировать счета без удаления истории. |
| metadata | JSONB | Технические данные: публичные адреса (для крипты), маски карт, настройки синхронизации. |
| created_at | TIMESTAMPTZ | Дата создания. |

**Primary Key:** `(id, internal_user_id)` — составной ключ для жесткой привязки к владельцу.

**Foreign Key:** `parent_id` ссылается на `wallets(id)` *того же* пользователя.

**Index:** `(internal_user_id, parent_id)` — для быстрого построения дерева счетов в UI.

## 1.2. Таблица: `envelopes` (Logical Layer)

**Назначение:** Логические конверты. Отвечают на вопрос «Зачем деньги?». Здесь реализуется приоритизация бюджета и целеполагание.

| Поле | Тип данных | Описание и Инварианты |
| --- | --- | --- |
| id | UUID | Part of PK. Уникальный ID конверта. |
| internal_user_id | UUID | Part of PK. Владелец. |
| parent_id | UUID (FK) | Ссылка на родителя (группировка: «Автомобиль» -> «Бензин»). |
| name | VARCHAR(100) | Название (Еда, Налоги, Tesla, Подушка). |
| envelope_type | VARCHAR(50) | Типы конвертов:- obligation (аренда, долги — высший приоритет)- reserve (налоги, амортизация)- saving (цели)- free_spend (ежедневные траты)- system_residue (системный остаток). |
| priority | INTEGER | Приоритет наполнения (1-100). Используется алгоритмом Waterfall при распределении дохода. |
| target_amount | NUMERIC | Целевая сумма (Nullable). Нужно для расчета прогресса цели. |
| target_date | DATE | Дедлайн цели. Критично для расчета Goal Lag (отставания от графика). |
| is_active | BOOLEAN | Флаг активности. |
| metadata | JSONB | Визуализация (иконка, цвет), настройки ИИ (тон напоминаний). |
| created_at | TIMESTAMPTZ | Дата создания. |

**Primary Key:** `(id, internal_user_id)`.

**Инвариант:** Сумма средств во всех конвертах пользователя должна математически совпадать с суммой средств на всех кошельках (∑W=∑E).

## 1.3. Таблица: `assets` (Context Anchors)

**Назначение:** Имущество, генерирующее расходы. Мы не трекаем рыночную стоимость актива в реальном времени (это не Ledger), но используем его как «якорь» для аналитики расходов (TCO — Total Cost of Ownership) и прогнозов Nostradamus.

| Поле | Тип данных | Описание и Инварианты |
| --- | --- | --- |
| id | UUID | Part of PK. Уникальный ID актива. |
| internal_user_id | UUID | Part of PK. Владелец. |
| name | VARCHAR(100) | Название (Tesla Model 3, Квартира на Ленина). |
| asset_type | VARCHAR(50) | vehicle (Транспорт), real_estate (Недвижимость), equipment (Техника), other. |
| is_active | BOOLEAN | true — владею, false — продал (архив). История трат сохраняется. |
| metadata | JSONB | Технические данные для предиктивной аналитики (VIN, дата следующего ТО, параметры страховки). |
| created_at | TIMESTAMPTZ | Дата добавления. |

**Связи:** Поле `asset_id` в таблице транзакций (Layer 2) ссылается сюда, позволяя отделить «Бензин для машины жены» от «Бензина для моей машины», даже если категория у них одинаковая.

# Слой: 2. The Ledger Core (Ядро Реестра и Когнитивный Буфер)

**Описание:** Этот слой отвечает за детерминированное хранение финансовых событий. Здесь действуют строгие математические инварианты, а операции `UPDATE` и `DELETE` физически запрещены для основной таблицы транзакций.

## 2.1. Таблица: `ledger_transactions` (The Immutable Ledger)

**Назначение:** Главный журнал операций. Единый источник правды для всех балансов. **Ключевой принцип:** Любое изменение прошлого (исправление ошибки) производится только через создание новой корректирующей записи (`is_reversal`), сохраняя аудиторский след.

| Поле | Тип данных | Описание и Инварианты |
| --- | --- | --- |
| id | UUID | Part of PK. Уникальный неизменяемый ID транзакции. |
| internal_user_id | UUID | Part of PK. Владелец данных. Обеспечивает секционирование и RLS. |
| message_id | VARCHAR(255) | Ссылка на сообщение в чате (chat_messages). Позволяет группировать несколько транзакций (доход + налог + комиссия) в одно событие. |
| wallet_id | UUID (FK) | Физическая нога: Откуда/куда ушли деньги (Ref: wallets). Если NULL, используется системный счет. |
| envelope_id | UUID (FK) | Логическая нога: Назначение денег (Ref: envelopes). Обязательно для соблюдения ∑Wallets≡∑Envelopes. |
| project_id | UUID (FK) | (Nullable) Привязка к проекту для расчета P&L и изоляции экономики бизнеса. |
| asset_id | UUID (FK) | (Nullable) Привязка к активу (Ref: assets). Например, расходы на "Tesla". |
| transaction_kind | VARCHAR(20) | Тип операции: income, expense, transfer, adjustment (корректировка), tax_reservation. |
| amount_original | NUMERIC(18, 8) | Сумма в валюте операции. Высокая точность для крипто-активов. |
| currency_code | VARCHAR(10) | FIX: Код валюты операции (USD, USDT, BTC). Записывается в момент транзакции. |
| fx_rate_snapshot | NUMERIC(18, 8) | Зафиксированный курс к базовой валюте пользователя на момент операции (Minute-Precision). |
| amount_base | NUMERIC(18, 2) | Сумма, пересчитанная в базовую валюту: amount_original * fx_rate_snapshot. |
| category_slug | VARCHAR(100) | Ссылка на системный справочник categories_dictionary (Admin Layer). |
| subcategory_slug | VARCHAR(100) | Детализация категории (например, grocery внутри food). |
| merchant_name | VARCHAR(255) | Имя контрагента. Может ссылаться на merchant_profiles через логику бэкенда. |
| user_note | TEXT | Заметка пользователя или AI-синтез смысла транзакции. |
| tags | JSONB | Массив пользовательских тегов. Тег hidden активирует Shadow Layer (скрытие из отчетов). |
| is_reversal | BOOLEAN | true, если это сторнирующая запись (исправление ошибки). |
| occurred_at | TIMESTAMPTZ | Реальное время события (по словам пользователя или дате чека). |
| created_at | TIMESTAMPTZ | Системное время записи в БД (Audit Time). |
| metadata | JSONB | Технические данные: ID чека в S3, версия AI-модели, trace_id. |

**CHECK:** `amount_base` должен математически соответствовать произведению `original` на `fx_rate`.

**Immutability:** Триггер `BEFORE DELETE OR UPDATE` должен блокировать любые изменения строк.

**Atomicity:** Запись в эту таблицу атомарно обновляет `user_snapshots` (Слой 3).

## 2.2. Таблица: `pending_layer` (The Cognitive Buffer)

**Назначение:** Буферная зона («Карантин») для транзакций, требующих подтверждения («Минимального волевого акта»). Здесь хранятся гипотезы ИИ и асинхронные события из блокчейна, которые еще не стали частью Ledger.

| Поле | Тип данных | Описание и Инварианты |
| --- | --- | --- |
| id | UUID | Part of PK. Уникальный ID черновика. |
| internal_user_id | UUID | Part of PK. Владелец. Изолирует черновики транзакций. |
| message_id | VARCHAR(255) | Ссылка на chat_messages. Позволяет кнопкам «Подтвердить/Отклонить» в чате знать, какую запись активировать. |
| source_type | VARCHAR(50) | Источник события: ocr_parser (чек), crypto_sync (блокчейн), nostradamus (прогноз), recurring (подписка). |
| proposed_data | JSONB | Гипотеза транзакции: Полный слепок данных для переноса в Ledger. Важно: Поле currency внутри JSON поддерживает строки до 10 символов (USDT). |
| status | VARCHAR(20) | pending, confirmed, rejected, expired. |
| confidence_score | NUMERIC(3, 2) | Уверенность ИИ (0.00 - 1.00). Если score низкий, UI подсвечивает поля, требующие внимания. |
| urgency_score | VARCHAR(10) | low, medium, high. Определяет, нужно ли пушить уведомление или ждать дайджеста (Anti-Spam). |
| expires_at | TIMESTAMPTZ | TTL (обычно 10 дней). Авто-удаление мусора. |
| metadata | JSONB | Обоснование ИИ («Выбрал категорию Еда, так как мерчант McDonald's»), ссылки на фрагменты чека. |


--------------------------------------------------------------------------------

## 2.3. Таблица: `tags_metadata` (User Folksonomy)

**Назначение:** Хранилище личных тегов пользователя. В отличие от системных категорий (`categories_dictionary` в Admin Layer), теги создаются пользователем динамически (начинаются с `#`).

| Поле | Тип данных | Описание и Инварианты |
| --- | --- | --- |
| id | UUID | Part of PK. Уникальный ID тега. |
| internal_user_id | UUID | Part of PK. Владелец тега. |
| tag_name | VARCHAR(100) | Текст тега (без #). Например, trip2026. |
| color_code | VARCHAR(7) | HEX цвет для UI. |
| is_active | BOOLEAN | Флаг активности (для скрытия старых тегов из подсказок). |

**Инвариант:** Теги используются в массиве `tags` таблицы `ledger_transactions` как простые строки, а эта таблица хранит их настройки и цвета для UI.

# Слой: 3. Business Logic & Obligations (Долги, Проекты и Налоги)

**Описание:** Этот слой отвечает за управление будущими потоками (долги, подписки), изоляцию экономики проектов и автоматический расчет чистой прибыли.


--------------------------------------------------------------------------------

## 3.1. Таблица: `obligations` (Debt & Receivables)

**Назначение:** Управление долгами и дебиторской задолженностью. В Sana долги — это не отрицательный баланс кошелька, а параллельная сущность, влияющая на прогноз ликвидности.

| Поле | Тип данных | Описание и Инварианты |
| --- | --- | --- |
| id | UUID | Part of PK. Уникальный ID обязательства. |
| internal_user_id | UUID | Part of PK. Владелец. Обеспечивает RLS. |
| project_id | UUID (FK) | (Nullable) Ссылка на проект. Позволяет учитывать долг в P&L проекта (например, невыплаченный гонорар). |
| merchant_id | UUID (FK) | Ссылка на merchant_profiles (Admin Layer). Жесткая привязка к контрагенту. |
| counterparty_name | VARCHAR(100) | Fallback имя контрагента, если нет профиля мерчанта. |
| obligation_kind | VARCHAR(20) | payable (мы должны), receivable (нам должны). |
| amount_total | NUMERIC | Изначальная сумма обязательства. |
| amount_remaining | NUMERIC | Текущий остаток. Уменьшается автоматически триггерами при привязке транзакции погашения в Ledger. |
| currency_code | VARCHAR(10) | FIX: Валюта долга (USD, USDT). Может отличаться от базовой. |
| due_date | DATE | Дедлайн. Критически важен для модуля Nostradamus (прогноз кассовых разрывов). |
| status | VARCHAR(20) | active, settled (погашен), overdue (просрочен). |
| metadata | JSONB | Условия (процентная ставка, график платежей). |
| created_at | TIMESTAMPTZ | Дата создания. |
| updated_at | TIMESTAMPTZ | Время последнего изменения. |

## 3.2. Таблица: `recurring_patterns` (Nostradamus Base)

**Назначение:** Реестр регулярных платежей (подписки, аренда). Служит базой для модуля прогнозирования **Nostradamus**, позволяя предвидеть расходы до их совершения.

| Поле | Тип данных | Описание и Инварианты |
| --- | --- | --- |
| id | UUID | Part of PK. Уникальный ID паттерна. |
| internal_user_id | UUID | Part of PK. Владелец. |
| name | VARCHAR(100) | Название (Netflix, Хостинг, Аренда). |
| amount_estimated | NUMERIC | Ожидаемая сумма списания. |
| currency_code | VARCHAR(10) | FIX: Валюта подписки. |
| periodicity | VARCHAR(20) | weekly, monthly, yearly. |
| next_date | DATE | Дата следующего платежа (триггер для уведомлений). |
| envelope_id | UUID (FK) | Ссылка на конверт, из которого планируется списание. |
| is_active | BOOLEAN | Активен ли паттерн. |

## 3.3. Таблица: `projects` (Business Containers)

**Назначение:** Контейнеры для бизнес-целей. Проект объединяет транзакции, налоги и долги в единую экономическую единицу («микро-бизнес» внутри кошелька).

| Поле | Тип данных | Описание и Инварианты |
| --- | --- | --- |
| id | UUID | Part of PK. Уникальный ID проекта. |
| internal_user_id | UUID | Part of PK. Владелец. |
| name | VARCHAR(100) | Название (Логотип, Стройка дачи). |
| budget_total | NUMERIC | Плановый бюджет или сумма контракта. |
| currency_code | VARCHAR(10) | FIX: Валюта учета проекта. Все P&L расчеты приводятся к ней. |
| start_date | DATE | Дата начала. |
| deadline | DATE | Дедлайн (влияет на прогнозы выплат). |
| status | VARCHAR(20) | active, completed, on_hold, archived. |
| archived_at | TIMESTAMPTZ | Время архивации (триггерит TTL для удаления связанных чатов). |
| metadata | JSONB | Специфические настройки (иконка, цвет). |

## 3.4. Таблица: `tax_rules` (Tax Engine Config)

**Назначение:** Правила автоматического резервирования налогов. Позволяет системе превращать «грязный доход» в «чистую прибыль» в момент транзакции.

| Поле | Тип данных | Описание и Инварианты |
| --- | --- | --- |
| id | UUID | Part of PK. Уникальный ID правила. |
| internal_user_id | UUID | Part of PK. Владелец. |
| project_id | UUID (FK) | (Nullable) Ссылка на проект. Если указано, правило применяется приоритетно ко всем доходам проекта. |
| wallet_id | UUID (FK) | (Nullable) Ссылка на физический счет (например, карта ИП). |
| tax_mode | VARCHAR(1) | Режим работы:A (Revenue) — % с оборота.B (Profit) — доходы минус расходы.V (Manual) — ручное управление. |
| tax_rate | NUMERIC(5, 4) | Ставка налога (например, 0.0600 для 6%). |
| tax_envelope_id | UUID (FK) | Конверт резерва, куда блокируются средства. |
| deductible_categories | JSONB | Список слагов категорий для вычета (для режима B). |
| is_active | BOOLEAN | Флаг активности правила. |

**Locked State:** Средства, попавшие в `tax_envelope_id`, исключаются из `Safe-to-Spend`.

## 3.5. Таблица: `project_balances` (Materialized P&L)

**Назначение:** Агрегаты P&L (Profit & Loss) в реальном времени. Обновляется триггерами при любом изменении в Ledger или Obligations.

| Поле | Тип данных | Описание и Инварианты |
| --- | --- | --- |
| project_id | UUID | PK/FK. Ссылка на проект. |
| internal_user_id | UUID | FK. Владелец. |
| total_income | NUMERIC | Валовый доход (Revenue). |
| total_expenses | NUMERIC | Прямые расходы (OpEx). |
| tax_reserved | NUMERIC | Накопленный налоговый резерв. |
| pending_payables | NUMERIC | Долги подрядчикам (сумма obligations типа payable). |
| pending_receivables | NUMERIC | Ожидаемые поступления (сумма obligations типа receivable). |
| net_profit | NUMERIC | Чистая прибыль: Income - Expenses - Tax - Payables. |
| last_transaction_at | TIMESTAMPTZ | Время последнего обновления баланса. |

`INSERT/UPDATE` в `ledger_transactions` с `project_id` -> пересчет строки.

Изменение `obligations` -> пересчет полей `pending_*` и `net_profit`.

# Слой: 4. Cognitive Context & Performance (Когнитивный слой и Снапшоты)

**Описание:** Этот уровень управляет контекстом диалога (память ИИ), мультимодальной историей (текст, фото) и кэшированием состояния для мгновенных ответов (Дашборд).

## 4.1. Таблица: `chat_sessions` (Context Containers)

**Назначение:** Управляет «памятью» ИИ и жизненным циклом диалогов. Позволяет Дирижёру понимать, о чем идет речь в конкретный момент (о проекте, о личном или о глобальных финансах), и изолирует контексты друг от друга.

| Поле | Тип данных | Описание и Инварианты |
| --- | --- | --- |
| id | UUID | Part of PK. Уникальный ID сессии. |
| internal_user_id | UUID | Part of PK. Владелец сессии. |
| title | VARCHAR(100) | Тема диалога (например, «Обсуждение монитора»). Генерируется ИИ на основе первых сообщений. |
| context_entity_type | VARCHAR(20) | Тип фокуса внимания: project, envelope, asset, global. |
| context_entity_id | UUID | ID сущности фокуса (например, project_id). Позволяет ИИ автоматически фильтровать данные Ledger только по этому проекту. |
| expires_at | TIMESTAMPTZ | TTL. Время автоматической архивации сессии. Временные диалоги живут 30 дней, проектные — пока жив проект. |
| last_message_at | TIMESTAMPTZ | Время последнего сообщения (для сортировки в UI). |
| metadata | JSONB | Настройки личности агента (например, Sana Zen) и язык общения для этой сессии. |
| created_at | TIMESTAMPTZ | Дата создания. |

**Изоляция:** История чатов хранится отдельно от финансового реестра. Удаление сессии не удаляет транзакции из Ledger.

## 4.2. Таблица: `chat_messages` (Multimodal History)

**Назначение:** Единый лог взаимодействия. Хранит связь между словами пользователя и транзакциями в Ledger через `message_id`. Это обеспечивает доказательную базу: «Я записал этот расход, потому что ты прислал вот это фото чека».

| Поле | Тип данных | Описание и Инварианты |
| --- | --- | --- |
| id | UUID | Part of PK. Уникальный ID сообщения. |
| session_id | UUID | FK. Ссылка на сессию из chat_sessions. |
| internal_user_id | UUID | Part of PK. Владелец. |
| role | VARCHAR(20) | Автор сообщения: user, assistant, system (для объявлений Broadcast). |
| content | TEXT | Текст сообщения или JSON-ответ агента. |
| message_id | VARCHAR(255) | Critical Link. Уникальный ID сообщения. По этому полю транзакции в ledger_transactions связываются с исходным приказом пользователя. |
| content_type | VARCHAR(20) | text, image (чек), voice (голосовое), system_event. |
| attachment_url | VARCHAR | Ссылка на объект в зашифрованном хранилище (S3). Фото и аудио удаляются после обработки согласно политике приватности. |
| metadata | JSONB | Технический след: использованные токены, ID модели ИИ, OCR-текст чека. |
| created_at | TIMESTAMPTZ | Время отправки. |

**Атомарность:** Одно сообщение может породить N транзакций (групповая обработка), все они будут иметь одинаковый `message_id`.

## 4.3. Таблица: `user_snapshots` (The Dashboard Engine)

**Назначение:** «Горячее» состояние системы. Агрегирует данные из всех таблиц в одну строку на пользователя. Служит «единым окном» для ИИ-агентов, позволяя отвечать на вопросы о балансе за миллисекунды без выполнения тяжелых SQL-запросов к истории.

| Поле | Тип данных | Описание и Инварианты |
| --- | --- | --- |
| internal_user_id | UUID | PK. Анонимный ID пользователя (отношение 1:1). |
| net_worth_base | NUMERIC | Общий капитал: Активы минус Обязательства в базовой валюте. |
| safe_to_spend | NUMERIC | Безопасный остаток: Ликвидные средства минус Налоговые резервы и Приоритетные конверты. |
| total_tax_reserve | NUMERIC | Сумма, заблокированная во всех налоговых конвертах. |
| crypto_valuation | NUMERIC | Текущая рыночная стоимость всех крипто-активов в базовой валюте. |
| wallets_summary | JSONB | Кэш балансов физических счетов (для быстрого рендеринга UI). |
| envelopes_summary | JSONB | Кэш прогресса по целям и конвертам. |
| obligations_summary | JSONB | Сводка по долгам: {"total_receivable": ..., "total_payable": ...}. |
| projects_pnl | JSONB | Краткий статус прибыли по активным проектам (net_profit по каждому ID). |
| last_ledger_id | UUID | ID последней учтенной транзакции (для контроля синхронизации). |
| updated_at | TIMESTAMPTZ | Время последнего обновления триггером. |

**Триггерное обновление:** Любой `INSERT` в `ledger_transactions` атомарно обновляет эту таблицу.

**Математическая чистота:** В снапшоте всегда проверяется равенство ∑Wallets≡∑Envelopes. Если оно нарушено, система сигнализирует о сбое.

## 4.4. Таблица: `balance_snapshots_history` (Historical Analytics)

**Назначение:** «Холодное» состояние. Ежедневные (EOD — End of Day) слепки для построения графиков динамики капитала и burn-rate.

| Поле | Тип данных | Описание и Инварианты |
| --- | --- | --- |
| id | UUID | Part of PK. Уникальный ID записи истории. |
| internal_user_id | UUID | Part of PK. Владелец. |
| snapshot_date | DATE | Дата среза (обычно 23:59:59 по таймзоне пользователя). |
| total_balance_base | NUMERIC | Общая сумма активов во всех кошельках в базовой валюте. |
| total_obligations_net | NUMERIC | Чистая позиция по долгам (Нам должны минус Мы должны). |
| snapshot_data | JSONB | Полный архивный слепок балансов всех счетов и конвертов на конец дня. |
| created_at | TIMESTAMPTZ | Время создания записи. |

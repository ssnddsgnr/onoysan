Этот документ описывает реализацию принципов **Identity Split** (Разрыв личности) и **Shared Sovereignty** (Совместный доступ). Здесь мы определяем таблицы, которые отвечают на вопросы «Кто ты?» и «На что ты имеешь право?», при этом физически изолируя эти знания от вопроса «Сколько у тебя денег?».


--------------------------------------------------------------------------------

**Концепция:** Identity Isolation & Sovereignty (Изоляция Личности и Суверенитет) **Схема БД:** `auth` (отдельная схема для изоляции прав доступа) **Назначение:** Управление входом, профилем и правами доступа. Этот слой служит шлюзом, который транслирует внешние идентификаторы (Telegram ID, Email) в анонимные внутренние UUID для финансового ядра.


--------------------------------------------------------------------------------

# 1. Шлюз Аутентификации (The Gateway)

Таблица `auth_identities` — это единственное место в системе, где внешний мир соприкасается с внутренним. Она реализует механизм **Identity Injection**: при входе система находит здесь пользователя и выдает токен с `internal_user_id`, после чего забывает про Telegram ID,.

## 1.1. Таблица: `auth.auth_identities`

| Поле | Тип данных | Описание и Инварианты |
| --- | --- | --- |
| id | UUID | PK. Технический ID записи. |
| internal_user_id | UUID | Master Key. Единый анонимный ID пользователя, используемый во всей системе (Ledger, Wallets). Ссылка 1:N (один юзер может иметь несколько методов входа),. |
| provider_type | VARCHAR(50) | Тип провайдера: telegram, email, apple_id. |
| external_id | VARCHAR(255) | ID во внешней системе. Хранится в зашифрованном виде (Encryption at Rest) симметричным ключом из Vault. Нужен для обратной отправки сообщений. |
| identity_hash | VARCHAR(255) | Хэш внешнего ID (Argon2 + соль). Используется для быстрого поиска при входе (SELECT ... WHERE hash = ?) без дешифровки external_id. |
| created_at | TIMESTAMPTZ | Дата привязки метода входа. |
| last_seen_at | TIMESTAMPTZ | Время последней активности. Используется для TTL сессий. |
| status | VARCHAR(20) | active, blocked, deleted. Позволяет мгновенно отозвать доступ через конкретный канал. |
| provider_metadata | JSONB | Кэш публичных данных (никнейм в ТГ, ссылка на аватар) для отображения в UI приветствия. |

**Инварианты безопасности:**

**Uniqueness:** Уникальный индекс на `(provider_type, identity_hash)` предотвращает дублирование аккаунтов.

**No Leaks:** Финансовое ядро (`ledger`) никогда не делает `JOIN` с этой таблицей.

# 2. Профиль и Метаданные (The Encrypted Profile)

Таблица `users_metadata` хранит настройки персонализации. Данные здесь разделены на публичные (для поиска друзей) и приватные (для ИИ).

## 2.1. Таблица: `auth.users_metadata`

| Поле | Тип данных | Описание и Инварианты |
| --- | --- | --- |
| internal_user_id | UUID | PK. Связь 1:1 с auth_identities. |
| nickname | VARCHAR(50) | Unique. Публичное имя (@alex_fin). Основной инструмент для поиска людей и «Социального оверлея». |
| is_discoverable | BOOLEAN | Если false (Stealth Mode), пользователя нельзя найти по никнейму. |
| encrypted_display_name | TEXT | Зашифрованное имя для обращения ИИ (напр., «Алексей»). Расшифровывается только в оперативной памяти в момент генерации ответа. |
| timezone | VARCHAR(50) | Часовой пояс (напр., Asia/Bishkek). Критически важен для модуля Nostradamus (закрытие дня, прогнозы). |
| base_currency | VARCHAR(10) | Основная валюта отчетности (USD, KGS). В ней считаются снапшоты Net Worth. |
| language_code | VARCHAR(5) | Код языка (ru, en). Определяет локализацию интерфейса и промптов ИИ. |
| is_language_manual | BOOLEAN | Флаг жесткой фиксации языка (запрет на авто-переключение ИИ). |
| ui_preferences | JSONB | Настройки темы, блюра балансов, формата дат. |
| ai_settings | JSONB | Настройки личности ИИ (тон голоса: «Финдиректор» или «Друг», уровень эмпатии). |
| onboarding_status | VARCHAR(50) | Этап обучения (wallet_added, first_transaction). |

# 3. Совместный Суверенитет (Shared Sovereignty)

Таблица `access_grants` реализует **RBAC** (Role-Based Access Control). Это механизм, позволяющий делегировать доступ к финансам без передачи паролей (например, семейный бюджет или корпоративные расходы).

## 3.1. Таблица: `auth.access_grants`

| Поле | Тип данных | Описание и Инварианты |
| --- | --- | --- |
| id | UUID | PK. Уникальный ID гранта. |
| grantor_id | UUID | Владелец ресурса (кто выдал права). Ссылка на internal_user_id. |
| grantee_id | UUID | Получатель прав (кому выдали). Ссылка на internal_user_id. |
| resource_type | VARCHAR(20) | Тип ресурса: wallet, project, envelope. |
| resource_id | UUID | ID конкретного ресурса (например, ID кошелька «Семейная карта»). |
| role | VARCHAR(20) | Уровень доступа (см. ниже). |
| expires_at | TIMESTAMPTZ | Время истечения прав (для временного доступа). Если NULL — доступ бессрочный. |
| created_at | TIMESTAMPTZ | Дата выдачи. |

**Ролевая модель (Roles):**

`viewer` — Только просмотр баланса и истории.

`editor` — Право создавать транзакции (запись в Ledger).

`requester` — Право отправлять запросы на выдачу средств (Pending Layer).

`manager` — Право одобрять запросы других (в рамках лимитов).

**Логика безопасности (RLS):** Все запросы к финансовым таблицам (`wallets`, `ledger_transactions`) автоматически фильтруются через эту таблицу. Пользователь видит ресурс, ЕСЛИ (он владелец) ИЛИ (есть активный грант в `access_grants`).

# 4. Контекст Чатов (Cognitive Memory)

Хотя чаты являются частью когнитивного слоя, их метаданные (сессии) тесно связаны с идентификацией и правами доступа.

## 4.1. Таблица: `auth.chat_sessions`

| Поле | Тип данных | Описание |
| --- | --- | --- |
| id | UUID | PK. ID сессии. |
| internal_user_id | UUID | Владелец сессии. |
| title | VARCHAR(100) | Тема диалога (авто-генерация ИИ). |
| context_entity_type | VARCHAR(20) | Привязка к контексту: project, envelope, global. |
| context_entity_id | UUID | ID сущности. Позволяет ИИ «видеть» только данные конкретного проекта в этом чате. |
| expires_at | TIMESTAMPTZ | TTL сессии. Обычные чаты живут 30 дней, проектные — пока жив проект. |

# 5. Политики Безопасности Слоя

## 5.1. PII Sanitization (Очистка данных)

Перед передачей данных из этого слоя в ИИ (через Дирижёра):

**Запрещено:** Передавать `external_id` (Telegram ID), Email.

**Разрешено:** Передавать `nickname`, расшифрованное `display_name` (только в рантайме), `timezone`, `ai_settings`,.

## 5.2. Hashing & Encryption

**Поиск:** Осуществляется только по `identity_hash` (Argon2). Это необратимый хэш. Даже если база утечет, злоумышленник не сможет восстановить Telegram ID пользователей без полного перебора.

**Коммуникация:** Обратная связь (отправка ответа в Telegram) возможна благодаря дешифровке `external_id` ключом, который хранится в **Vault** (память процесса), а не в БД.

## 5.3. Изоляция (Air-Gap)

Таблицы схемы `auth` находятся в той же физической БД, что и `ledger`, но доступ к ним регламентирован на уровне ролей PostgreSQL. Финансовые хранимые процедуры (PL/pgSQL) не имеют прав `SELECT` к таблице `auth_identities`.

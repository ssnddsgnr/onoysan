**Статус:** Final Technical Specification



**Слой:** System Domain (Глобальные знания и Администрирование)



**Описание:** Содержит общесистемные справочники, технические метрики, логи аудита и инструменты управления платформой. Является «Единым источником правды» для всех пользователей системы.



---



# 1. Слой Глобальных Знаний (Global Knowledge)



Справочники, которые служат эталоном для классификации и расчетов.



## 1.1. Таблица: `fx_rates_history` (Minute-Precision FX)



**Назначение:** Глобальный архив курсов валют. Использует механизм «затухания» (Rollup): хранит минутные данные за последние 24 часа, часовые за месяц и дневные за всё время. Обеспечивает историческую точность Ledger.



| Поле | Тип данных | Описание и Инварианты |

| --- | --- | --- |

| **pair_hash** | `TEXT` | **Part of PK.** Хэш пары (напр., `USD_USDT`, `BTC_ETH`). Ускоряет поиск. |

| **fetched_at** | `TIMESTAMPTZ` | **Part of PK.** Точное время фиксации курса. |

| **resolution** | `VARCHAR(10)` | Масштаб данных: `1m` (минуты), `1h` (часы), `1d` (дни). |

| **base_currency** | **`VARCHAR(10)`** | **FIX:** Исходная валюта. Расширено для поддержки тикеров >3 символов. |

| **target_currency** | **`VARCHAR(10)`** | **FIX:** Валюта котировки. |

| **rate_avg** | `NUMERIC` | Средневзвешенный курс за период (для аналитики). |

| **rate_last** | `NUMERIC` | Курс закрытия периода. Копируется в `ledger_transactions` при совершении операции. |

| **provider_slug** | `VARCHAR(50)` | Источник данных (`binance`, `chainlink`, `fixer`). Обеспечивает Provider Agnostic подход. |

| **is_verified** | `BOOLEAN` | `true`, если курс подтвержден минимум двумя независимыми источниками. |



**Индексы:** `INDEX (fetched_at, resolution)` — для быстрого поиска ближайшего курса к транзакции (Snapshot on Write).



## 1.2. Таблица: `categories_dictionary` (Global Taxonomy)



**Назначение:** Централизованная таксономия категорий. Служит эталоном для ИИ при классификации транзакций. Пользователь не может удалять эти категории, но может создавать личные теги поверх них.



| Поле | Тип данных | Описание и Инварианты |

| --- | --- | --- |

| **slug** | `VARCHAR(100)` | **PK.** Уникальный код (напр., `food_grocery`). Ключ для записи в Ledger. |

| **parent_slug** | `VARCHAR(100)` | Ссылка на родителя (FK Self-reference). Иерархия: `food` -> `food_grocery`. |

| **display_name** | `JSONB` | Локализованные названия (`{"en": "Groceries", "ru": "Продукты"}`). |

| **icon_emoji** | `VARCHAR(10)` | Эмодзи для UI (напр., 🛒). |

| **is_system** | `BOOLEAN` | Защита от удаления системных критических категорий (напр., `transfer`, `adjustment`). |



## 1.3. Таблица: `merchant_profiles` (Context Knowledge)



**Назначение:** Глобальная база знаний о торговых точках. Позволяет ИИ «узнавать» бренды по сырому тексту из банковской выписки и автоматически предлагать категорию.



| Поле | Тип данных | Описание и Инварианты |

| --- | --- | --- |

| **id** | `UUID` | **PK.** Уникальный ID профиля. |

| **name** | `VARCHAR(255)` | Эталонное имя (`Starbucks`, `Netflix`, `Иван Дизайнер`). |

| **type** | `VARCHAR(50)` | Тип контрагента: `business` (магазин) или `person` (человек). |

| **default_category_slug** | `VARCHAR(100)` | FK -> `categories_dictionary(slug)`. Категория по умолчанию. |

| **brand_logo_url** | `VARCHAR` | Ссылка на логотип/аватар для красивых выписок. |

| **metadata** | `JSONB` | Реквизиты, MCC-коды, альтернативные имена для парсера. |

# 2. Слой Технического Состояния (Infrastructure & State)



Таблицы для обслуживания бэкенда, мониторинга и интеграций.



## 2.1. Таблица: `blockchain_cursors` (Sync State)



**Назначение:** Хранит состояние синхронизации для крипто-движка `sana-crypto-sync`. Фиксирует номер последнего обработанного блока, чтобы избежать дублирования транзакций или пропусков.



| Поле | Тип данных | Описание и Инварианты |

| --- | --- | --- |

| **id** | `UUID` | **PK.** Уникальный ID курсора. |

| **chain_id** | `VARCHAR(50)` | Идентификатор сети (`bitcoin`, `ethereum`, `polygon`). |

| **last_block_height** | `BIGINT` | Номер последнего успешно просканированного блока. |

| **last_sync_at** | `TIMESTAMPTZ` | Время последней синхронизации. Если `NOW() - last_sync_at > 10 min`, ИИ сообщает о сбое. |

| **status** | `VARCHAR(20)` | `active`, `stalled`, `maintenance`. Влияет на работу воркера. |

| **metadata** | `JSONB` | Технические данные: хэш блока, токен пагинации провайдера. |



**Индексы:** `UNIQUE (chain_id)` — только один активный курсор на сеть.



## 2.2. Таблица: `ai_usage_metrics` (Cost Control)



**Назначение:** Технический учет ресурсов ИИ. Фиксирует каждый запрос к LLM (Gemini, Claude), подсчитывая токены и стоимость. Необходима для контроля Unit-экономики.



| Поле | Тип данных | Описание и Инварианты |

| --- | --- | --- |

| **id** | `UUID` | **PK.** Уникальный ID метрики. |

| **request_source** | `VARCHAR(50)` | Инициатор: `conductor`, `ocr_parser`, `nostradamus`. |

| **model_name** | `VARCHAR(50)` | Использованная модель (`gemini-1.5-pro`, `claude-3-opus`). |

| **input_tokens** | `INTEGER` | Количество токенов в промпте. |

| **output_tokens** | `INTEGER` | Количество токенов в ответе. |

| **execution_time_ms** | `INTEGER` | Время выполнения (мониторинг задержек). |

| **cost_estimated** | `NUMERIC(10, 6)` | Расчетная стоимость запроса в USD. |

| **trace_id** | `UUID` | ID трассировки для связки с логами. |

| **created_at** | `TIMESTAMPTZ` | Время совершения запроса. |



*Примечание: Текст запросов здесь не сохраняется (Data Sanitization).*



## 2.3. Таблица: `_sqlx_migrations` (Schema Versioning)



**Назначение:** Служебная таблица для управления версиями схемы БД. Гарантирует, что код бэкенда работает с ожидаемой структурой данных.



| Поле | Тип данных | Описание и Инварианты |

| --- | --- | --- |

| **version** | `BIGINT` | **PK.** Номер версии миграции (напр., `202601180001`). |

| **description** | `TEXT` | Название миграции. |

| **installed_on** | `TIMESTAMPTZ` | Время применения. |

| **success** | `BOOLEAN` | Статус выполнения. |

| **checksum** | `BYTEA` | Хэш файла миграции (защита от подмены). |

| **execution_time** | `BIGINT` | Время выполнения в наносекундах. |

# 3. Слой Управления и Безопасности (Governance & Broadcast)



## 3.1. Таблица: `system_audit_logs` (Immutable Audit)



**Назначение:** Неизменяемый журнал критических событий безопасности. Фиксирует действия администраторов и изменения прав доступа. **Запрещено** удалять записи из этой таблицы.



| Поле | Тип данных | Описание и Инварианты |

| --- | --- | --- |

| **id** | `UUID` | **PK.** Уникальный ID записи лога. |

| **admin_id** | `UUID` | ID администратора или сервисного аккаунта. |

| **event_type** | `VARCHAR(50)` | Тип события: `access_grant_change`, `system_update`, `user_ban`. |

| **target_table** | `VARCHAR(50)` | Имя затронутой таблицы. |

| **target_record_id** | `UUID` | ID записи, над которой совершено действие. |

| **changes_diff** | `JSONB` | Снапшот изменений `{"old": ..., "new": ...}`. |

| **ip_address** | `INET` | IP-адрес инициатора. |

| **created_at** | `TIMESTAMPTZ` | Точное время события. |



---



## 3.2. Таблица: `system_announcements` (Broadcast Service)



**Назначение:** Канал коммуникации с пользователями. Позволяет отправлять уведомления (о техработах, релизах) без нарушения целостности Ledger. Эти сообщения «впрыскиваются» в ленту чата.



| Поле | Тип данных | Описание и Инварианты |

| --- | --- | --- |

| **id** | `UUID` | **PK.** Уникальный ID объявления. |

| **title** | `VARCHAR(255)` | Заголовок («Технические работы»). |

| **content** | `TEXT` | Текст сообщения (Markdown). |

| **type** | `VARCHAR(50)` | Категория: `maintenance`, `release`, `alert`. |

| **target_group** | `JSONB` | Фильтры: `{"os": "ios"}`, `{"geo": "KG"}`. |

| **is_critical** | `BOOLEAN` | `true` = показать поверх интерфейса (Alert). |

| **starts_at** | `TIMESTAMPTZ` | Время начала показа. |

| **expires_at** | `TIMESTAMPTZ` | Время окончания (TTL). |

| **created_by** | `UUID` | ID администратора (ссылка на аудит). |

Этот документ является **техническим сердцем** системы. В архитектуре Sana мы отказались от того, чтобы Бэкенд (Rust) занимался финансовой арифметикой. Вся логика — от проводки транзакции до расчета налогов — инкапсулирована в **PL/pgSQL**.

Это гарантирует **атомарность** (все или ничего) и **детерминизм** (одни и те же данные всегда дают один результат, независимо от версии API).


--------------------------------------------------------------------------------

**Концепция:** Logic in Database (Логика внутри данных) **Роль:** API базы данных. Бэкенд вызывает эти функции, а не пишет `INSERT/UPDATE` напрямую. **Инвариант:** Ни одна транзакция не считается завершенной, пока не выполнены все триггеры (Snapshot, Tax, Balance Check).

# 1. Схема `ledger`: Ядро Транзакций

Здесь живут функции, изменяющие состояние кошельков и конвертов.

## 1.1. `ledger.fn_create_transaction(payload JSONB)`

## 1.2. `ledger.fn_reverse_transaction(tx_id UUID, reason TEXT)`

**Механизм «Право на ошибку».** Реализует паттерн сторнирования вместо удаления.

**Логика:**Находит исходную транзакцию по `tx_id`.Создает **новую** транзакцию с флагом `is_reversal = true`.Инвертирует сумму (`amount * -1`).Копирует все метаданные (категорию, проект), добавляя пометку «Reversal of {tx_id}».Атомарно обновляет балансы.

## 1.3. `ledger.fn_reality_sync(wallet_id UUID, real_balance NUMERIC)`

**Синхронизация реальности.** Используется, когда пользователь вручную корректирует остаток («На карте сейчас 500, а не 450»).

# 2. Схема `tax`: Налоговый Движок (Tax Engine)

Автоматизация налоговых обязательств. Эти функции вызываются триггерами при появлении дохода.

## 2.1. `tax.fn_calculate_tax_reserve()` (Trigger Function)

**Триггер:** `AFTER INSERT` на `ledger_transactions` (только для `type = 'income'`).

**Логика:**Проверяет наличие активного правила в `tax_rules` для `wallet_id` или `project_id`.**Режим A (Оборот):** Считает `reserve = amount * rate`.**Режим B (Прибыль):** Проверяет накопленные расходы проекта, вычитает их из базы, считает налог с дельты.**Action:** Создает **техническую транзакцию** внутри Ledger: перевод средств из конверта «Доход» в конверт «Налоговый резерв» (`tax_envelope_id`).Помечает исходную транзакцию как `tax_processed = true`.

## 2.2. `tax.fn_apply_deduction(expense_tx_id UUID)`

**Учет расходов (для Режима B).** Вызывается, если расход помечен как «уменьшающий налоговую базу».

**Логика:**Уменьшает накопительный итог налогооблагаемой базы проекта.Если был излишне зарезервированный налог — создает транзакцию возврата средств из «Налогового резерва» в «Свободные деньги» проекта.

# 5. Обработка ошибок (Exception Handling)

Все функции обернуты в блоки `BEGIN ... EXCEPTION`.

**ERR_INVARIANT_VIOLATION**** (P0001):** Выбрасывается, если ∑W=∑E. Бэкенд транслирует это как «Системная ошибка целостности».

**ERR_NEGATIVE_BALANCE**** (P0002):** Попытка списать больше, чем есть (если кошелек не допускает овердрафт).

**ERR_ACCESS_DENIED**** (42501):** Нарушение RLS.

# Резюме для разработчика БД

**Бизнес-логика — здесь.** Не пиши формулы налогов в Rust. Пиши их в `tax.fn_...`.

**JSON на входе.** Функции принимают богатые JSON-объекты, чтобы не менять сигнатуру функции при добавлении нового поля (например, тега).

**Триггеры — наше все.** Снапшоты и налоги должны считаться сами. Бэкенд просто делает `INSERT` и получает результат.

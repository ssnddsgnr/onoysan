Этот слой критически важен, так как он содержит «Глобальные знания» (курсы валют, категории) и техническое состояние системы, но не содержит пользовательских денег.

Это **Layer 0**, фундамент, на который опираются все остальные слои.


--------------------------------------------------------------------------------

**Концепция:** System Domain (Глобальные знания и Администрирование) **Схема БД:** `system` **Назначение:** Единый источник справочных данных, технических метрик и логов безопасности. Данные в этом слое являются общими для всех пользователей или служебными.


--------------------------------------------------------------------------------

# 1. Слой Глобальных Знаний (Global Knowledge)

*Справочники, служащие эталоном для классификации, оценки стоимости и работы ИИ.*

## 1.1. Таблица: `fx_rates_history` (Валютный движок)

**Назначение:** Глобальный архив курсов валют и криптовалют. Реализует механику **Minute-Precision FX** («Заморозка времени»). Любая транзакция в Ledger ссылается на курс из этой таблицы, зафиксированный в минуту совершения операции.

| Поле | Тип | Описание и Инварианты |
| --- | --- | --- |
| pair_hash | TEXT | PK (Composite). Хэш пары (напр., USD_BTC, EUR_KGS). Ускоряет поиск. |
| fetched_at | TIMESTAMPTZ | PK (Composite). Точное время фиксации курса. |
| resolution | VARCHAR(10) | Масштаб свечи: 1m (минута), 1h (час), 1d (день). |
| base_currency | VARCHAR(10) | Исходная валюта (напр., USD). |
| target_currency | VARCHAR(10) | Валюта котировки (напр., BTC). |
| rate_avg | NUMERIC | Средневзвешенный курс за период (Open+Close+High+Low / 4). |
| rate_last | NUMERIC | Курс закрытия. Именно это значение копируется в Ledger. |
| provider_slug | VARCHAR(50) | Источник (binance, chainlink). Принцип Provider Agnostic. |
| is_verified | BOOLEAN | true, если курс подтвержден консенсусом 2+ источников. |

**Политика хранения (Rollup Policy):** Для экономии места применяется агрегация старых данных:

**1m (Hot):** Хранятся 24 часа.

**1h (Warm):** Хранятся 30 дней.

**1d (Cold):** Хранятся вечно.

## 1.2. Таблица: `categories_dictionary` (Таксономия)

**Назначение:** Централизованное дерево категорий. Служит семантическим эталоном для ИИ-агентов. Пользователи не могут удалять эти записи, но могут создавать свои теги поверх них.

| Поле | Тип | Описание |
| --- | --- | --- |
| slug | VARCHAR(100) | PK. Уникальный код (food_grocery, transport_taxi). |
| parent_slug | VARCHAR(100) | Ссылка на родителя. Строит иерархию (food -> food_grocery). |
| display_name | JSONB | Локализация ({"en": "Food", "ru": "Еда"}). |
| icon_emoji | VARCHAR(10) | Визуализация для UI (🛒, 🚕). |
| is_system | BOOLEAN | Защита от изменений критических категорий (transfer, tax). |
| ai_description | TEXT | Промпт для LLM, объясняющий смысл категории. |

## 1.3. Таблица: `merchant_profiles` (Контекст Мерчантов)

**Назначение:** База знаний о брендах. Позволяет парсеру превращать сырой текст из чека ("STARBUCKS COFFEE #23") в чистую сущность ("Starbucks") с логотипом и категорией по умолчанию.

| Поле | Тип | Описание |
| --- | --- | --- |
| id | UUID | PK. |
| name | VARCHAR(255) | Эталонное имя бренда. |
| match_patterns | JSONB | Regex-паттерны для поиска в сырых строках (["uber*trip", "yandex.taxi"]). |
| default_category_slug | VARCHAR(100) | FK на categories_dictionary. Авто-категоризация. |
| brand_logo_url | VARCHAR | Ссылка на логотип для UI. |
| is_subscription | BOOLEAN | Маркер для Nostradamus: этот мерчант часто является подпиской. |

# 2. Слой Технического Состояния (Technical State)

*Служебные таблицы для воркеров и мониторинга.*

## 2.1. Таблица: `blockchain_cursors` (Синхронизация)

**Назначение:** Хранит состояние сканера `sana-crypto-sync`. Фиксирует последний обработанный блок для каждой сети, чтобы избежать пропусков или дублей при чтении блокчейна.

| Поле | Тип | Описание |
| --- | --- | --- |
| id | UUID | PK. |
| chain_id | VARCHAR(50) | Сеть (bitcoin, ethereum, polygon). |
| last_block_height | BIGINT | Номер последнего просканированного блока. |
| last_sync_at | TIMESTAMPTZ | Время последней активности. Используется для Health Check. |
| status | VARCHAR(20) | active, stalled, maintenance. |

## 2.2. Таблица: `ai_usage_metrics` (Unit-экономика)

**Назначение:** Учет потребления токенов LLM. Необходима для контроля затрат и выставления лимитов, так как каждый запрос стоит денег.

| Поле | Тип | Описание |
| --- | --- | --- |
| id | UUID | PK. |
| request_source | VARCHAR(50) | Инициатор (conductor, ocr_parser). |
| model_name | VARCHAR(50) | Модель (gemini-1.5-flash, claude-3-opus). |
| input_tokens | INTEGER | Токенов на входе. |
| output_tokens | INTEGER | Токенов на выходе. |
| cost_estimated | NUMERIC | Расчетная стоимость в USD. |
| trace_id | UUID | ID для трассировки логов (без PII). |

## 2.3. Таблица: `import_batches` (Миграция данных)

**Назначение:** Управление массовыми импортами из CSV/Excel. Позволяет откатить неудачный импорт целиком, так как все транзакции импорта привязываются к `batch_id`.

# 3. Слой Управления и Безопасности (Governance)

*Инструменты администратора и каналы оповещения.*

## 3.1. Таблица: `system_audit_logs` (Аудит)

**Назначение:** Неизменяемый журнал действий администраторов и изменений прав доступа. **Запрещено** удалять записи из этой таблицы.

| Поле | Тип | Описание |
| --- | --- | --- |
| id | UUID | PK. |
| event_type | VARCHAR(50) | access_grant_change, system_update. |
| target_table | VARCHAR(50) | Какая таблица затронута. |
| changes_diff | JSONB | Снапшот изменений {"old": ..., "new": ...}. |
| created_at | TIMESTAMPTZ | Время события. |

## 3.2. Таблица: `system_announcements` (Broadcast)

**Назначение:** Канал вещания. Позволяет отправлять уведомления (техработы, релизы) пользователям прямо в чат, минуя финансовый контекст.

| Поле | Тип | Описание |
| --- | --- | --- |
| id | UUID | PK. |
| content | TEXT | Текст сообщения (Markdown). |
| type | VARCHAR(50) | maintenance, release, alert. |
| target_group | JSONB | Фильтр ({"os": "ios"}, {"geo": "KG"}). |
| is_critical | BOOLEAN | true — показать поверх интерфейса (Alert). |
| expires_at | TIMESTAMPTZ | TTL объявления. |

# 4. Политики Доступа (Access Control)

Этот слой изолирован от пользовательских данных:

**ReadOnly:** Пользовательские процессы (бэкенд при обработке чата) имеют доступ к таблицам `fx_rates`, `categories` и `merchants` только на чтение.

**Service Write:** Только специализированные спутники (`sana-crypto-sync`, `sana-fx-engine`) имеют права на запись в свои таблицы состояния.

**No PII:** В схеме `system` строго запрещено хранить персональные данные пользователей.

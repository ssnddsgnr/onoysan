Документ описывает структурную схему взаимодействия, визуальные потоки и функциональное распределение между платформами, что соответствует описанию архитектурных схем и логического устройства системы. Определяет функциональное распределение между интерфейсами Sana, следуя принципу **«Один мозг — три окна»**.


--------------------------------------------------------------------------------

# 1. Mobile App (iOS / Android) — «Ежедневный навигатор»

Основной хаб для взаимодействия «на бегу». Фокус на приватности и скорости.

**Bimodal UI:** Полноценный переключатель между **Cognitive Chat** и **Visual Dashboard**.

**Локальное хранилище:** Полная история переписки хранится в локальной базе данных (SQLite/Realm) для мгновенного доступа.

**Compliance-статус:** В приложении отсутствуют ссылки на оплату и разделы «Магазин». Статус подписки отображается как информационная плашка: *«Sana Premium активен до...»*.

**Безопасность:** Биометрический вход (FaceID/TouchID/PIN) и защита от скриншотов в финансовых разделах.

**Центр уведомлений:** Прием критических пушей от Nostradamus о кассовых разрывах.


--------------------------------------------------------------------------------

# 2. Web Interface — «Центр суверенитета и управления»

Полнофункциональное зеркало приложения для Desktop, являющееся юридическим и финансовым ядром системы.

**Consent Gate:** Единственная точка для принятия ToS, Privacy Policy и юридических согласий.

**Billing Hub (Stripe):** Эксклюзивная зона для привязки карт, выбора тарифов и оплаты подписки.

**Access Management Hub:** Визуальный конструктор прав доступа (`access_grants`). Список всех лиц, имеющих доступ к вашим счетам, с кнопкой мгновенного отзыва прав.

**Data Mobility:** Загрузка тяжелых файлов для импорта из других систем и скачивание PDF/Excel отчетов.

**Identity Management:** Связка Telegram-аккаунтов, смена Email и управление ключами шифрования персональных данных.


--------------------------------------------------------------------------------

# 3. Telegram Bot — «Эфемерный шлюз ввода»

Легкая точка входа для текстового и голосового взаимодействия.

**Эфемерность:** История сообщений внутри бота не хранится. Бот — это «труба» для передачи данных в Ledger.

**Multi-modal Ingestion:** Прием фото чеков, «голосовух» и быстрых команд (MVA).

**Маркетинговая свобода:** Бот может отправлять прямые ссылки на оплату через Stripe и информировать о скидках.

**Smart Routing:** Бот отвечает пользователю только в том случае, если последняя активность была зафиксирована именно в Telegram.

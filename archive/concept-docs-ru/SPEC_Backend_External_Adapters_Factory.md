# 1. Философия: Архитектура Адаптеров

Бизнес-логика Sana (Ledger, Tax Engine, Nostradamus) никогда не должна зависеть от прихотей внешних API или изменений цен у вендоров. Мы строим систему, где замена Gemini на Claude или Binance на CoinGecko — это вопрос смены переменной окружения.

## 1.1. Паттерн Фабрики (The Factory Pattern)

В коде ядра (`sana-core`) запрещено прямое использование SDK вендоров (например, `openai-sdk` или `ethers-rs` внутри контроллеров). Вместо этого ядро обращается к **Фабрике Адаптеров**, которая в рантайме возвращает реализацию абстрактного типажа (Rust Trait),. **Поток вызова:**

**Core:** `let ai_service = AdapterFactory::get_ai_provider(Config::FastLoop);`

**Factory:** Читает конфиг, видит `provider: "groq"`, инжектирует API-ключ из Vault.

**Result:** Возвращает структуру `GroqAdapter`, реализующую типаж `ModelProvider`.

**Action:** Core вызывает метод `ai_service.invoke_agent(...)`, не зная, кто физически исполняет запрос.

# 2. AI Model Provider: Когнитивная Фабрика

Управляет доступом к LLM. Ключевая особенность — динамическое переключение моделей и управление когнитивным потоком через Backend.

## 2.1. Типаж `ModelProvider`

Определяет единый интерфейс для всех нейросетей:

```
#[async_trait]
trait ModelProvider {
    async fn invoke_agent(&self, payload: AgentPayload) -> Result<AgentResponse, AIError>;
}
```

## 2.2. Режимы работы (Loop Strategy)

Фабрика выбирает провайдера на основе контекста задачи,:

**Fast Loop (Groq / Gemini Flash):****Задачи:** Парсинг чеков (OCR), классификация транзакций, простые ответы в чате.**Приоритет:** Скорость (<500ms).

**Задачи:** Глубокая аналитика (Nostradamus), эмпатичные ответы (Sana Zen), сложные финансовые советы.

**Приоритет:** Качество рассуждений и большое контекстное окно.

## 2.3. Middleware: PII Sanitization

Адаптер автоматически применяет правила очистки данных. Перед отправкой JSON-пейлоада провайдеру, слой **Sanitizer** вырезает любые PII (телефоны, email), заменяя их на токены `[REDACTED]`, соблюдая принцип «Air-Gap» для личной информации,.

## 2.4. Протокол «Static Prompts, Dynamic Data»

Бэкенд не формирует текстовые промпты ("Ты финансовый помощник..."). Он отвечает исключительно за сбор и доставку **Контекста** (данных). Сами инструкции (System Prompts) инкапсулированы внутри конфигурации Агентов.

# 3. Exchange Rate Provider: Валютная Истина

Обеспечивает работу системы «Minute-Precision FX». Курсы валют — это не константа, а поток данных, который не должен зависеть от одного источника.

## 3.1. Типаж `ExchangeRateProvider`

```
trait ExchangeRateProvider {
    async fn get_rates(&self, pairs: Vec<Pair>) -> Result<Vec<Rate>, FXError>;
}
```

## 3.2. Логика Агрегации (Consensus Logic)

Адаптер реализует логику «Справедливой цены» для исключения манипуляций или сбоев одного источника,:

**Multi-Source Fetch:** Запрашивает курс одновременно у `BinanceAdapter`, `CoinGeckoAdapter` и `FixerAdapter` (для фиата).

**Outlier Removal:** Отбрасывает экстремумы (самый высокий и самый низкий курс).

**Averaging:** Вычисляет среднее значение оставшихся источников.

**Verification:** Если курс подтвержден минимум двумя источниками, он помечается как `is_verified = true` в таблице `fx_rates_history`.

# 4. Node Provider: Блокчейн-Шлюз

Используется спутником `sana-crypto-sync` для чтения данных из блокчейнов. Мы не доверяем одной ноде.

## 4.1. Типаж `ChainInformer`

Абстрагирует методы получения балансов и истории транзакций (`get_balance`, `get_history`).

## 4.2. Ротация и Failover

**Round-Robin:** Фабрика чередует запросы между Infura, Alchemy и собственными нодами для распределения нагрузки и обхода Rate Limits.

**Consistency Check:** Для критических операций (крупные депозиты) адаптер может запросить данные у двух провайдеров и сверить `block_hash`, чтобы убедиться в отсутствии форка или отставания ноды.


--------------------------------------------------------------------------------

# 5. Notification Provider: Коммуникационный Шлюз

Абстракция над каналами доставки сообщений пользователю (помимо основного ответа в чате).

## 5.1. Реализации

**EmailAdapter:** Используется для отправки OTP-кодов при входе (через SMTP или сервисы типа SendGrid).

**TelegramPushAdapter:** Используется для критических алертов (например, от Nostradamus о кассовом разрыве), даже если пользователь не активен в данный момент в чате.

**SystemBroadcast:** Интеграция с таблицей `system_announcements` для массовых уведомлений.

# 6. Инфраструктура: Безопасность и Отказоустойчивость

## 6.1. Secret Injection

API-ключи (например, `GEMINI_API_KEY`, `ETHERSCAN_TOKEN`) **никогда** не хранятся в коде или Docker-образе,.

**Механизм:** При старте пода (`sana-core`), Kubernetes инжектирует секреты из **HashiCorp Vault** в переменные окружения процесса.

**Инициализация:** Фабрика считывает их при создании структуры адаптера (`new(api_key: String)`).

## 6.2. Circuit Breaker

Фабрика реализует паттерн «Предохранитель». Если внешний сервис (например, Stripe или одна из LLM) начинает возвращать ошибки 500 или тайм-ауты:

Адаптер временно «размыкает цепь», прекращая отправку запросов на этот источник.

Автоматически переключается на резервного провайдера (Failover).

Это гарантирует, что сбой внешнего API не заблокирует потоки Ядра.

# Резюме

**External Adapters Factory** превращает Backend Sana в модульный конструктор, защищенный от внешнего хаоса. Ядро остается чистым и детерминированным, делегируя взаимодействие с нестабильным внешним миром специализированным, взаимозаменяемым и изолированным адаптерам.

Документ содержит финальную техническую логику, правила Identity Injection и алгоритмы работы наставника (Mentor Mode), что делает его техническим фундаментом (Законом) для системы. Процесс регистрации в Sana спроектирован так, чтобы минимизировать «трение» при входе, обеспечивая при этом полную юридическую прозрачность и соблюдение архитектурного принципа **Identity Split** (Разрыв идентичности).


--------------------------------------------------------------------------------

# 1. Сценарии входа (Providers)

Sana доверяет верификацию личности проверенным методам, избавляя пользователя от необходимости создавать и запоминать пароли:

**Telegram ID:** Основной метод для быстрого взаимодействия. Система полностью доверяет Telegram как верификатору.

**Email (OTP):** Дополнительный или альтернативный метод входа через одноразовый пароль.

**Принцип суверенитета:** Пользователь может связать несколько методов входа с одним анонимным профилем для отказоустойчивости доступа.


--------------------------------------------------------------------------------

# 2. Веб-шлюз согласия (Consent Gate)

Даже при инициации регистрации через Telegram-бота, система принудительно переводит пользователя в **Web-интерфейс** для фиксации юридических соглашений.

**Первый контакт:** При команде `/start` в боте Sana Zen приветствует пользователя и передает ссылку на «Веб-шлюз».

**Юридическая фиксация:** В веб-интерфейсе пользователь принимает Условия использования (ToS) и Политику конфиденциальности.

**Сбор согласий:** Пользователь дает явное согласие на обработку финансовых данных и сбор необходимых метаданных, что фиксируется в базе данных с привязкой к IP и времени.

**Аутентификация Биллинга:** Поскольку оплата подписки (Stripe) производится вне сторов, веб-шлюз сразу знакомит пользователя с платежной инфраструктурой.


--------------------------------------------------------------------------------

# 3. Технический протокол Identity Injection

После подтверждения согласий в веб-шлюзе, бэкенд выполняет процедуру инъекции идентичности:

**Создание UUID:** Система генерирует анонимный `internal_user_id`, который становится единственным ключом в финансовом ядре (Ledger).

**Маппинг:** В таблице `auth.auth_identities` фиксируется связь внешнего ID (например, Telegram ID) с внутренним UUID.

**Изоляция:** С этого момента бэкенд-модули оперируют только анонимным UUID, физически не имея доступа к реальным именам или контактам пользователя в финансовых таблицах.


--------------------------------------------------------------------------------

# 4. Непрерывный онбординг (Continuous Onboarding)

После завершения регистрации Sana Zen активирует режим **Mentor Mode** («Живой наставник»).

**Обучение в бою:** Система не выдает все функции сразу, а раскрывает их по мере возникновения финансовой потребности (например, настройка налогового профиля при первом доходе).

**Минимальный шаг:** Для снижения когнитивной нагрузки и страха перед учетом, Zen разбивает первые действия пользователя на атомарные **MVA** (Минимальные волевые акты).

**Локализация:** Система автоматически определяет язык общения на основе метаданных Telegram или браузера, обеспечивая когнитивный комфорт с первого сообщения.


--------------------------------------------------------------------------------

# 5. Управление состоянием онбординга

Технический прогресс пользователя фиксируется в служебных таблицах:

**user_onboarding_milestones****:** Отслеживает ключевые этапы (первая транзакция, создание проекта, настройка налогов).

**feature_flags****:** Управляет доступностью модулей ИИ в зависимости от уровня финансовой зрелости пользователя.
